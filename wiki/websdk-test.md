## 문제 📄
- 챗봇을 웹페이지에 붙이는 연동 방식별 동작을 직접 확인할 수단이 필요. 고객 연동 문의에 실제로 돌려보고 답하고, 새 연동을 시작할 때 쓰는 최소 예제 모음(README).

## 내 역할
- 📄 저장소에 명시 없음. 🧠 사용자 확정(개인 프로젝트)으로 기획·구현·문서·검증 전체.

## 기능 📄
- **세 가지 연동 방식, 화면 네 쪽**: `/v2.html`(V2 웹SDK), `/xi.html`(XI SDK), `/matrix.html`(V2 옵션 9·이벤트 5·메서드 7 전수 확인, 오류 재현), `/csp.html`(고객사 CSP에서 무엇을 열어야 하는지 모드별 확인).
- **띄우는 방식 선택**: 고정형 / 플로팅 / SDK 없이(iframe + postMessage). V2는 플로팅 인스턴스 미반환 문제를 래핑으로 해결, XI는 플로팅 기능이 없어 직접 구현, 플로팅은 챗봇 자리 안에서 열림(v0.21.1).
- 화면 입력 칸에서 host와 봇 ID만 바꿔 다른 챗봇 연결, `presets.json` 테스터 챗봇 프리셋(자격증명 금지·자동 차단), 비인증 옵션.
- 서버: `/config`(키 미노출), `/auth`(토큰 대리 발급, 실패 원인을 화면에 노출), `/sso` 데모.
- 자체 점검 `npm test`(약 59항목: 화면, 비밀 노출 여부, 서버 생존, 문서 링크, 프리셋 자격증명 검사), `npm run check:env`, `probe:auth`(토큰 실패 지점 단계별 진단).
- 문서: `docs/연동-가이드.md`(전부 직접 실행해 확인한 내용), `docs/SDK-결함-보고.md`(전달용 결함 보고).

## 기술 📄
- Node, Express 4, dotenv, 정적 HTML/JS/CSS(`sample.css` 통일), 스모크 테스트 스크립트. 현재 버전 0.21.1.
