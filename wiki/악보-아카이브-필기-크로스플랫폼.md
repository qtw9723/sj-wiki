> [!tip] 핵심 takeaway
> 📄 **필기는 iPad(애플펜슬)와 갤럭시탭(S펜) 양쪽에서 모두 가능해야 한다.** 사용자 확정 요구사항.
> 🧠 다행히 **필기 코드는 한 벌이면 된다** — Pointer Events가 표준이라 플랫폼 분기가 필요 없다. 갈리는 건 필기가 아니라 **PWA 환경(저장·설치·동기화)** 이다.
> 🧠 그래서 리스크는 **iOS 쪽에 몰려 있다.** 안드로이드는 대부분의 제약이 해당 없음.

---

## 1. 필기 구현은 플랫폼 공통 (🧠)

📄 Pointer Events는 2020년 7월부터 모든 주요 브라우저가 지원하는 표준(Baseline). 애플펜슬과 S펜 모두 같은 이벤트로 들어온다.

| 속성 | 값 | 용도 |
|---|---|---|
| `pressure` | 0~1 (미지원 기기는 활성 시 0.5) | 선 굵기 |
| `tiltX` / `tiltY` | 기울기 | 필요 시 |
| `twist`, `altitudeAngle`, `azimuthAngle` | 회전·각도 | 선택 |
| `pointerType` | `'pen'` / `'touch'` / `'mouse'` | ⚠️ **팜 리젝션의 핵심** |

→ **플랫폼별 분기 코드를 만들지 않는다.** 하나의 필기 엔진으로 양쪽을 커버한다.

## 2. 반드시 구현할 필기 규칙 3가지 (🧠)

> [!warning] 네이티브 앱이 OS에서 공짜로 받는 것을, 웹에서는 직접 해야 한다

### 2-1. 팜 리젝션 — 자동으로 되지 않는다
손바닥이 화면에 닿으면 그대로 선이 그어진다. 반드시 직접 필터링한다.
- `event.pointerType === 'pen'` 일 때만 그린다
- 캔버스에 `touch-action: none` 을 건다 (브라우저 기본 스크롤/줌 가로채기 방지)
- 🧠 손가락 필기를 허용할지는 **설정으로 뺀다**(기본 off). 펜 없는 팀원도 있을 수 있다.

### 2-2. `getCoalescedEvents()` — 선 품질이 여기서 갈린다
펜은 화면 갱신 주기보다 훨씬 촘촘히 좌표를 뿌린다. 이걸 쓰지 않으면 중간 점들이 버려져 **빠르게 그을 때 선이 각지게** 나온다.
- `pointermove` 안에서 `event.getCoalescedEvents()`를 순회해 모든 점을 반영한다
- 🧠 "필기 앱 느낌이 나느냐"가 사실상 이 한 줄에 달려 있다. 프로토타입에서 반드시 넣고 비교해볼 것.

### 2-3. 좌표는 0~1 상대값
화면 크기·확대율이 기기마다 다르다. 절대 픽셀 저장 금지. (→ [[악보-아카이브-메모-동기화]] §3)

## 3. 테스트 매트릭스 (🧠 — 프로토타입에서 전부 확인)

| 기기 | 브라우저 | 우선순위 | 확인 항목 |
|---|---|---|---|
| iPad | Safari | ⭐ 필수 | 필기 지연·PWA 설치·저장 유지 |
| 갤럭시탭 | **삼성 인터넷** | ⭐ 필수 | 🧠 갤럭시 **기본 브라우저**라 팀원 다수가 여기로 연다 |
| 갤럭시탭 | Chrome | 필수 | 기준 동작 |
| 양쪽 | **카카오톡 인앱 브라우저** | ⭐ 필수 | 🧠 실제 배포 경로. 여기서 세션·설치·캐싱이 깨진다 → [[악보-아카이브-뷰어-배포]] §2 |

> [!warning] 🧠 삼성 인터넷을 빠뜨리지 말 것
> Chromium 기반이라 대체로 Chrome과 같지만 **같다고 가정하고 넘어가면 안 된다.** 팀원들이 실제로 여는 건 크롬이 아니라 삼성 인터넷일 가능성이 높다.

## 4. PWA 환경 차이 — 여기가 진짜 갈림길 (📄 조사 2026-08-27)

| 항목 | Android Chrome / 삼성 인터넷 | iOS Safari |
|---|---|---|
| 앱 설치 | ✅ 명확한 설치 프롬프트 | △ "홈 화면에 추가"로만 |
| 오프라인 저장 | ✅ 여유 있음 | ⚠️ 제한 + 미사용 시 정리 가능 |
| 백그라운드 동기화 | ✅ 지원 | ❌ 미지원 — 포그라운드 복귀 시 처리 필요 |
| 푸시 알림 | ✅ 지원 | △ 홈 화면 설치한 PWA에서만 |

**설계에 미치는 영향 (🧠)**
- 메모 동기화는 **백그라운드 동기화에 의존하지 않는다.** iOS에 없으므로, **앱 복귀(포그라운드) 시점에 대기열을 밀어내는** 방식으로 통일한다 → [[악보-아카이브-메모-동기화]] §4. 이렇게 하면 양 플랫폼이 같은 코드로 돌아간다.
- 캐싱은 **"이번 주 세트만"** 전략을 양쪽 공통으로 적용한다. iOS 기준에 맞추면 안드로이드는 자동으로 여유롭다.
- 알림은 **당분간 카카오톡으로** 한다(📄 어차피 링크를 단톡방에 공유). 푸시 구현은 뒤로 미룬다 — 플랫폼별 편차가 크고 실익이 작다.

## 5. 판단 기준 (🧠)

프로토타입에서 확인한 뒤:

| 결과 | 판단 |
|---|---|
| 양쪽 다 필기 만족 | ✅ **PWA로 확정.** Capacitor 불필요 |
| 갤럭시만 만족, iPad 아쉬움 | 🤔 iPad만 네이티브 껍데기 검토 — 또는 iPad 사용자에게 감수 요청 |
| 양쪽 다 아쉬움 | ⚠️ **Capacitor로 전환.** 웹 코드는 재사용되므로 손실은 크지 않다 |

- 🧠 📄 양 플랫폼 지원이 요구사항이 된 이상, **한쪽만 되는 해법은 답이 아니다.** Capacitor는 iOS·Android를 모두 커버하므로 최악의 경우에도 퇴로가 있다.
