> [!tip] 핵심 takeaway (포트폴리오 관점)
> LLM이 매일 자동으로 쓰는 위키(174페이지)에 **보는 층(시각화·탐색)**을 얹은 작업이다. 핵심은 "더 잘 보이게"보다 **보는 도구가 콘텐츠를 건드리지 않게** 하는 경계 설계였다. 외부 도구(graphify)는 통째로 들이지 않고 아이디어 5개만 골라 가져왔고, 플러그인이 노트 26개를 몰래 다시 쓴 사고는 같은 날 찾아내 원인을 코드에서 특정하고 되돌린 뒤 금지 규칙으로 바꿨다.
> 이력서 한 줄: *"LLM 자동 위키에 무료 LLM(K-EXAONE) 기반 연결 제안 루프와 Obsidian 시각화 층을 구축. 도구가 데이터를 바꾸지 못하게 하는 원칙을 세우고, 플러그인의 일괄 재작성 사고를 당일 탐지·복구."*

## 1. 사용법 — 이럴 때 이 기능

### 1-1. 찾기
| 하고 싶은 것 | 기능 | 방법 |
|---|---|---|
| 단어로 본문 검색 | **Omnisearch** | Cmd+P → "Omnisearch: Vault search". 단축키(예: Cmd+Shift+O)를 지정해 두면 편하다. 오타가 있거나 단어 일부만 입력해도 찾는다 |
| 허브로 바로 이동 | **북마크** | 왼쪽 사이드바 북마크: index·내-프로필·포트폴리오·게임요소-라이브러리·공통-기술스택·에이전트-자동화-도구·건강검진 리포트·log·카테고리별 보기 |
| 카테고리별·최근 수정 순 보기 | **위키-보기 (Bases)** | `wiki/위키-보기.base`. 왼쪽 위에서 보기 전환(최근 업데이트 40개 / 프로젝트 / AI 동향 / 게임 요소 / 나머지). "최근 업데이트"를 보면 자동 위키화가 오늘 무엇을 고쳤는지 알 수 있다 |
| 미리보기와 함께 훑기 | **Notebook Navigator** | 파일 탐색기 자리의 두 칸 화면. 폴더 없이 평평한 위키라 **태그로 거르기**가 가장 유용하다 |

### 1-2. 읽으면서 맥락 잡기
- **링크 색 (Supercharged Links)**: 링크 색이 대상 페이지의 `category`를 나타낸다. 주황=프로젝트, 파랑=AI 동향, 보라=게임 요소, 빨강=보안, 초록=교회·악보, 청록=도구, 분홍=개념, 갈색=회의록, 회색=시스템. 그래프 색상 그룹과 같은 색이다.
- **참조 수 (Strange New Worlds)**: 링크와 제목 옆의 숫자는 그 페이지를 참조하는 곳의 수다. 숫자를 클릭하면 참조하는 페이지 목록이 뜬다.
- **Callout Manager / Colored Tags**: `[!tip]` 같은 콜아웃의 색·아이콘과 태그 색을 정한다.

### 1-3. 연결 구조 보기
- **로컬 그래프** (기본 기능): 지금 페이지 주변만 본다. 오른쪽 사이드바에 고정해 두기를 권한다.
- **ExcaliBrain**: Cmd+P → "ExcaliBrain: Open". 현재 노트를 가운데 두고 위·아래·옆으로 연결을 펼친다. 노드를 클릭해 이동하며 탐색한다. Dataview가 꼭 있어야 동작한다.
- **Extended Graph**: 전체 그래프 오른쪽 위의 토글로 켠다. 점 크기를 중심성(연결이 얼마나 많은지)으로 바꿔 허브를 키운다. 끄면 색상 그룹 그래프로 돌아간다.
- **전체 그래프**: 색상 그룹 10개, raw는 숨김, 연결이 끊긴 노드도 숨김.

### 1-4. 원하는 목록 만들기 (Dataview)
노트에 코드 블록을 넣으면 목록이 자동으로 채워진다. 원본 노트는 바뀌지 않는다.
````
```dataview
TABLE category, updated
FROM "wiki"
WHERE updated >= date(today) - dur(7 days)
SORT updated DESC
```
````
다른 예: `status: 진행중`인 프로젝트만 보기, 특정 `gl_*` 속성을 가진 게임 요소만 보기.

### 1-5. 기타
- **Iconic**: 파일을 우클릭 → 아이콘. 허브에만 다는 것을 권한다.
- **Excalidraw**: 손그림·다이어그램을 그린다. 그림은 `Excalidraw/` 폴더에 저장된다.

### 1-6. 하루 사용 흐름
1. 위키-보기의 **최근 업데이트**로 오늘 바뀐 페이지를 확인한다.
2. 링크 색과 참조 수로 중요한 연결을 고른다.
3. ExcaliBrain이나 로컬 그래프로 주변을 탐색한다.
4. 검색은 Omnisearch로 한다.

## 3. 설계 원칙 (이 작업에서 굳힌 것)
1. **보는 층은 쓰는 층을 건드리지 않는다.** 위키는 LLM 자동화(launchd 09:00·18:00)가 쓴다. 시각화 도구가 노트나 설정을 바꾸면 자동 커밋에 섞이고 원인 추적이 어려워진다. → 금지 목록: frontmatter 일괄 재작성, graph.json 덮어쓰기, 노트·폴더 자동 생성.
2. **새 메타데이터를 만들지 않고 기존 `category`를 재사용한다.** 그래프 색, 링크 색, Bases 보기가 모두 같은 필드를 읽는다. 새 카테고리를 만들면 graph.json과 링크 색 CSS **둘 다** 갱신한다.
3. **외부 도구는 아이디어만 가져온다.** graphify는 설치하지 않았다. LLM 제안도 사람이 판정한 뒤에만 링크로 만든다.
4. **비용과 약관 경계.** 무료 LLM(EXAONE)은 비상업 공개 위키에만 쓴다. 회사 기밀 vault(sj-wiki-work)에는 쓰지 않는다.
5. **멀티 기기.** 플러그인이 git으로 동기화되므로 모든 기기의 Obsidian 버전을 manifest의 `minAppVersion` 이상으로 맞춘다.
