> [!tip] 핵심 takeaway
> 🧠 **"앱스토어 없이, 소수가, 앱 업데이트 없이"** 쓸 거면 답은 **PWA**다. 웹을 고쳐 배포하면 앱 화면도 바로 바뀌고, 개발자 계정·심사·90일 빌드 갱신이 전부 필요 없다.
> 🧠 PWA는 새로 배울 기술이 아니라 **일반 웹앱 + manifest 1개 + 아이콘 + 메타 태그 몇 줄**이다. 서비스 워커는 오프라인·푸시가 필요할 때만 붙인다.
> 🧠 가장 큰 실무 함정은 **카카오톡 인앱 브라우저**다(설치 메뉴가 안 보임). 링크를 카톡으로 돌릴 땐 "Safari/크롬으로 열어주세요" 안내를 꼭 붙인다. → [[악보-아카이브-뷰어-배포]] §2와 같은 문제.

## 1. 결정 배경 (📄 사용자 조건)
- 📄 웹 기반 모바일 앱을 만들려 한다. 처음엔 WebView 방식을 생각했다.
- 📄 **App Store 등록은 하지 않는다.**
- 📄 사용자 수는 많지 않고, 간단하게만 쓴다.
- 📄 **앱 자체의 업데이트는 하지 않으려** 한다.
- 🧠 이 네 조건이 겹치면 WebView(TestFlight 배포)보다 PWA가 맞다. WebView는 앱 코드를 안 고쳐도 TestFlight 빌드가 90일 뒤 만료돼 결국 다시 올려야 하기 때문이다.

## 2. 방식 비교 (🧠)

| 방식 | 웹 수정이 앱에 반영? | iOS 배포 | 비용 | 비고 |
|---|---|---|---|---|
| **PWA** (홈 화면에 추가) | ✅ 즉시 | Safari에서 직접 추가 | 0원 | 심사 없음, 앱스토어 검색 불가 |
| WebView (URL 불러오기) | ✅ 즉시 | TestFlight / Ad Hoc / 앱스토어 | 연 $99 | 빌드 만료(90일) 관리 필요, "웹사이트만 감싼 앱"은 심사 거절 가능 |
| 번들 방식 (Capacitor 기본) | ❌ 재빌드·재배포 | 위와 동일 | 연 $99 | 오프라인 가능, 심사에 유리 |

**iOS 배포 대안 정리 (🧠)**
- **TestFlight**: 개발자 계정(연 $99). 외부 테스터 최대 10,000명, 첫 빌드는 베타 심사. 빌드 90일 만료.
- **Ad Hoc**: 기기 UDID 등록 최대 100대.
- **무료 Apple ID + Xcode**: 7일 만료, 본인 기기만. 공유용 아님.
- **비공개(Unlisted) 앱스토어 등록**: 결국 심사를 거침 → "등록 안 함" 조건과 안 맞음.
- ⚠ "엔터프라이즈 프로그램은 사내 직원용", "한국에 대체 마켓 없음"은 🧠 기억 기반이며 2026-11-05 기준 미검증. 정책은 바뀔 수 있으니 필요하면 다시 확인.

## 3. 일반 웹앱 vs PWA (🧠)
사용자 입장의 차이는 "앱처럼 보이고 앱처럼 열린다"가 거의 전부다.

| | 일반 웹앱 | PWA |
|---|---|---|
| 접속 | 브라우저에 주소 입력 | 홈 화면 아이콘 |
| 화면 | 주소창·탭 UI 보임 | 주소창 없이 전체 화면 |
| 아이콘·이름 | 스크린샷 같은 기본 아이콘 | 내가 지정한 아이콘·이름 |
| 오프라인 | 불가 | 서비스 워커로 가능(선택) |
| 푸시 알림 | 불가 | 가능(서비스 워커 + 사용자 허용) |

## 4. 최소 설정 체크리스트 (🧠)
1. **HTTPS**: Vercel 등에 배포하면 기본 제공.
2. **모바일 반응형**: 처음부터 모바일 기준으로 만든다. 웹을 고쳐도 레이아웃이 안 깨진다.
3. **아이콘**: 180×180(`apple-touch-icon`), 192×192, 512×512 PNG. 안드로이드용 maskable 512 한 장 권장(가장자리가 잘려도 되게 여백).
4. **`index.html` `<head>` 메타 태그**
   ```html
   <meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
   <meta name="apple-mobile-web-app-capable" content="yes">
   <meta name="apple-mobile-web-app-title" content="앱이름">
   <link rel="apple-touch-icon" href="/icon-180.png">
   <link rel="manifest" href="/manifest.json">
   ```
5. **`manifest.json`**
   ```json
   {
     "name": "앱 전체 이름",
     "short_name": "앱이름",
     "start_url": "/",
     "display": "standalone",
     "background_color": "#ffffff",
     "theme_color": "#ffffff",
     "icons": [
       { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" },
       { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png" },
       { "src": "/icon-512-maskable.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
     ]
   }
   ```
6. **서비스 워커**: 오프라인·푸시가 필요 없으면 생략.

## 5. 사용자 설치 방법 (🧠)
- **iPhone**: 반드시 **Safari**로 접속 → 공유 버튼 → "홈 화면에 추가".
- **안드로이드**: 크롬(또는 삼성 인터넷)으로 접속 → ⋮ 메뉴 → "앱 설치" 또는 "홈 화면에 추가". manifest가 맞으면 설치 배너가 자동으로 뜨기도 한다.
- ⚠ **카카오톡 인앱 브라우저**에서는 설치 메뉴가 안 보일 수 있다. 공유 시 "Safari/크롬으로 열어주세요" 안내 필수.

## 6. 만들 때 주의점 (🧠)
- 주소창이 없으니 **뒤로가기 버튼을 앱 안에 직접** 만들어 둔다.
- 노치·하단 바 영역은 `env(safe-area-inset-*)` CSS로 여백 처리한다.
- 외부 링크를 누르면 앱을 벗어나 브라우저로 넘어갈 수 있다.
- iOS 푸시는 **홈 화면에 추가한 PWA에서만**, 사용자가 직접 허용해야 한다. 알림이 핵심 기능이면 한계가 있다. 이때는 Capacitor로 감싸는 경로를 검토한다(→ [[악보-아카이브-뷰어-배포]] §3 "대안 경로").
- 앱스토어 검색은 안 된다. 링크나 QR코드로 공유한다.

## 7. 다른 개발자에게 보낼 카톡 메시지 (🧠 초안)
카카오톡은 마크다운이 안 보이므로 일반 텍스트로 작성했다.

```
[웹앱 앱화 방식 공유]

웹 프로젝트를 앱처럼 쓰게 하고 싶을 때, 앱스토어 없이 PWA로 하는 걸 추천해요.

■ 왜 PWA?
- 앱스토어 심사·개발자 계정($99/년) 불필요
- 웹을 고쳐 배포하면 앱 화면도 바로 반영 (앱 업데이트 과정 없음)
- iOS·안드로이드 코드 하나로 둘 다 커버
- WebView + TestFlight 방식은 빌드가 90일마다 만료돼서 관리가 번거로워요

■ 일반 웹앱에서 추가할 것 (이것만 하면 끝)
1) manifest.json (이름, 아이콘, start_url, "display": "standalone")
2) 아이콘 PNG: 180(apple-touch-icon) / 192 / 512
3) index.html head에 메타 태그
   - apple-mobile-web-app-capable = yes
   - apple-mobile-web-app-title
   - link rel="apple-touch-icon"
   - link rel="manifest"
4) HTTPS (Vercel 배포하면 자동)
5) 모바일 기준 반응형 UI
※ 서비스 워커는 오프라인/푸시 필요할 때만 붙이면 돼요.

■ 설치 방법 (사용자)
- iPhone: 꼭 Safari로 접속 → 공유 버튼 → 홈 화면에 추가
- 안드로이드: 크롬 → ⋮ → 앱 설치 / 홈 화면에 추가

■ 주의
- 카톡 인앱 브라우저에서는 설치 메뉴가 안 보여요. 링크 공유할 때 "Safari/크롬으로 열어주세요" 꼭 안내해주세요.
- 주소창이 없으니 앱 안에 뒤로가기 버튼을 직접 만들어 두세요.
- 아이폰 노치/하단 영역은 safe-area CSS로 처리
- iOS 푸시는 홈 화면에 추가한 PWA에서만 되고 사용자가 허용해야 해요. 알림이 핵심이면 Capacitor로 감싸는 걸 고려해보세요.
```

## 8. 의외의 연결점 (🧠 판단)
- 🧠 **[[AI-주간-소식-2026-W45]] W45-32 *"AI, 하이프에서 실용주의로"* ↔ 이 결정**: 같은 날 들어온 서로 무관한 자료인데 판단 방식이 같다. 그럴듯한 선택지(WebView 앱·앱스토어)보다 **조건에 맞는 최소 비용 경로**(PWA, 0원·심사 없음)를 먼저 고른다. 기술 선택에서 ROI를 먼저 묻는 습관은 [[mailer|CS SmartHub]]처럼 실사용자 요구에서 출발한 프로젝트를 설명할 때도 쓸 수 있는 포트폴리오 어휘다.
- 🧠 **카톡 공유문(§7) ↔ [[악보-아카이브-메모-동기화]]**: 공유문은 *"서비스 워커는 필요할 때만"* 이라고 권한다. 반대로 악보 아카이브처럼 오프라인 메모·저장이 핵심이면 서비스 워커와 iOS 저장 제약이 첫 설계 과제가 된다. 같은 PWA라도 **오프라인 요구 유무가 난이도를 가른다**.
