> [!tip] 핵심 takeaway
> 📄 사용자 요구(2026-10-23): 크롤러가 **Steam을 보고 가져오되 유저 평가를 기준**으로 하고, **게임 크리틱(평론가) 점수도 함께** 본다. 선별 기준은 **점수와 리뷰 수**.
> 🧠 [[게임요소-라이브러리]]의 `수집` 단계(`gl_status: 수집`)에 들어갈 **게임 후보를 사람이 고르는 대신 숫자로 거르는 입구**다. 특히 "유저는 높은데 평론가는 낮은(또는 반대) 게임"을 따로 표시해 두었으니, 요소를 뽑을 때 그쪽부터 보면 배울 게 많다.
> 코드: `tools/game-crawler/crawler.py` (표준 라이브러리만, 저장소 루트에서 실행). ⚠ 개발 환경에서 외부 접속이 안 돼 **실제 API로는 아직 실행해 보지 못했다** → 첫 실행은 `--limit 5`.

## 1. 무엇을 하나 (📄 확정 사항 2026-10-23, 사용자 확인)
- 크리틱 소스는 **OpenCritic과 Metacritic 둘 다**.
- 선별은 **점수와 리뷰 수** 기준으로 자동.
- 스크립트를 바로 작성하고 이 위키 문서로도 저장.

## 2. 데이터 소스

| 소스 | 용도 | 상태 |
|---|---|---|
| Steam `IUserReviewsService/GetAppReviews/v1` | 유저 긍정/부정 수 → 점수·리뷰 수 | 📄 공식 문서 확인 |
| SteamSpy (비공식) | 후보 목록 + 사전 필터용 긍정/부정 수 | 🧠 기억 기반, 미확인 (VERIFY) |
| OpenCritic (RapidAPI) | 평론가 점수 | 🧠 기억 기반, 이번 검색에서 미확인 (VERIFY) |
| Metacritic | 메타스코어 | 🧠 공식 API 없음. 약관 미확인 → **옵트인** |

### Steam 공식 API (📄 Steamworks 문서)
- 예전 `store.steampowered.com/appreviews/<appid>?json=1`은 **deprecated**, 대체는 `https://api.steampowered.com/IUserReviewsService/GetAppReviews/v1/`.
- 키는 선택. 앱 연동 퍼블리셔 키가 없으면 낮은 한도를 공유하고, 초과 시 HTTP 429. 익명 응답은 최대 10분 캐시.
- 파라미터는 `input_json`에 넣음. `languages: ["all"]`이면 전 언어, `num_per_page` 최대 100, `cursor`로 페이징.
- 점수 요약(`review_score`, `total_positive`, `total_negative`, `total_reviews`)은 **첫 페이지에서만, `review_type`이 all일 때만** 나온다 → 게임당 호출 1회로 선별 가능.
- 앱 목록(어떤 게임을 볼지)은 이 API로는 안 나온다 → SteamSpy 또는 사용자 목록(appid 파일)으로 해결.

## 3. 선별 규칙 (🧠 설계)
1. **사전 필터**: SteamSpy 수치로 리뷰 수 ≥ 1,000, 긍정 ≥ 80% (둘 다 옵션으로 변경 가능).
2. **공식 확인**: 통과한 게임만 GetAppReviews로 재확인 (호출 절약 + 정확도).
3. **정렬 = Wilson 하한(95%)**: 긍정 비율이 같아도 **리뷰가 많은 쪽이 위**. 리뷰 20개짜리 100%가 리뷰 5만 개짜리 96%를 이기지 못하게 하는 장치.
4. **평론가 병합**: OpenCritic·Metacritic 점수의 평균 vs 유저 긍정%. 차이 ≥ 15점이면 `유저>평론가` / `평론가>유저`, 그 외 `일치`, 못 찾으면 `평론가 없음`.
5. 이름이 **정확히 같을 때만** 평론가 점수 채택(오매칭이 누락보다 해롭다).

> [!note] 숫자 해석 주의 (🧠)
> 유저 긍정%와 평론가 점수는 **척도가 다르다**(비율 vs 평균 점수). 15점 차이 기준은 시작값일 뿐이므로 실제 결과를 보고 조정한다. 평론가 점수는 큰 게임 위주로만 존재해 인디는 `평론가 없음`이 많을 것.

## 4. 출력과 위키 연결 (🧠 설계)
1. 크롤러 → `raw/games/steam-critic-YYYY-MM-DD.json` + `.md` 요약 표.
2. 상위 게임을 `게임요소-사례-<게임>` 페이지로 만들고 `gl_status: 수집`.
3. 그 게임에서 반복되는 메커니즘을 요소 후보로 뽑아 `게임요소-메커니즘-…` 페이지로 분리(규약은 [[게임요소-라이브러리]] §4~5).
- 리뷰 본문은 위키에 그대로 쓰지 않는다. `--sample-reviews N`으로 받은 본문(400자 절단)은 **개인 분석용**이며 `.gitignore`로 커밋 제외([[게임요소-라이브러리]] §6의 복제 금지 원칙과 같은 취지).
- 이 저장소는 GitHub에서 **public**으로 보인다 → 크롤링 원본을 올릴 때 한 번 더 확인.

## 5. 실행 (📄 `tools/game-crawler/README.md`)
```bash
python tools/game-crawler/crawler.py --self-test                      # 모의 응답 검증
python tools/game-crawler/crawler.py --source steamspy-top --limit 5  # 첫 실행은 소량
RAPIDAPI_KEY=... python tools/game-crawler/crawler.py --source steamspy-top --opencritic --metacritic
```
- 외부 접속이 되는 PC에서 실행해야 한다(🧠 이 위키 작업 환경은 외부 사이트 접속이 막혀 있음). 기존 Windows PC 크롤러([[웹-크롤링-기초]])와 같은 방식으로 작업 스케줄러에 올릴 수 있다.
- 키는 환경변수(`RAPIDAPI_KEY`, `STEAM_API_KEY`)로만 받고 `.env`는 `.gitignore` 대상.

## 6. 정제·분류 단계 (📄 `tools/game-crawler/process.py`, 🧠 설계)
크롤링 결과를 위키에 쌓기 전에 **확인 → 분류 → 사람 결정**을 거친다.
1. **검증·정제(자동)**: 게임이 아닌 항목(DLC·데모·소프트웨어)·중복 appid·요약 없음은 **사유와 함께 탈락**, 긍정 비율 재계산 불일치·이름 없음·Early Access는 **경고**로 표시.
2. **게임 단위 장르 분류(자동)**: Steam 장르 + SteamSpy 태그를 `genre_map.json`으로 [[게임요소-라이브러리]] §4-3의 `gl_genre` 어휘에 매핑. 매핑에 없는 태그는 **미분류 목록**으로 모아 어휘표에 추가할지 사람이 결정.
3. **요소 추출(사람 확인)**: 리뷰를 읽고 메커니즘 후보를 `gl_type`·`gl_domain`·`gl_experience`와 함께 제안 → 근거(몇 게임에서 몇 번 언급)를 달아 **대화에서 약 10개 게임씩 확인** → 승인된 것만 `게임요소-…` 페이지(`gl_status: 수집`)로. API 자동화는 하지 않는다(어휘 밖 값이 새는 것을 막기 위해, 🧠 판단).
4. **신규 구분**: `raw/games/state.json`으로 이미 본 게임을 기록해 매일 돌려도 새 게임만 🆕 표시.
- 아직 없음: 리뷰 폭탄(최근 리뷰 급변) 탐지.
- 평론가 이름 매칭은 정확 일치만 채택하므로 별도 신뢰도 검사는 두지 않았다.

## 7. 매일 아침 실행과 테스트 결과 (2026-10-23)
- 📄 **실제 수집은 시험하지 못했다.** Claude 클라우드 환경과 데스크톱 앱 작업 VM 모두 `api.steampowered.com`이 프록시에서 **403**(허용 목록 밖, GitHub은 통과). 같은 이유로 Claude 예약 작업으로는 지금 Steam 수집이 돌지 않는다.
- 📄 데스크톱 앱 VM에서 연결 폴더 안의 `git clone`은 파일 삭제가 막혀 있어 실패했다(잠금 파일을 지우지 못함). 그 결과 `Documents\sj-wiki`에 `.git` 껍데기만 남았다 → 지워도 되는 빈 폴더.
- 📄 **확정 사항(2026-10-24, 사용자 확인)**: PC가 항상 켜져 있으므로 **① PC에서 직접 실행**으로 간다 → `tools/game-crawler/setup_windows.bat` 한 번 실행(모의 테스트 → 실제 5개 수집 시험 → 07:30 작업 등록).
- 🧠 (참고) 선택지는 둘이었다: **① PC에서 Windows 작업 스케줄러로 직접 실행**(`run_daily.bat`, 07:30 — 사용자 선택) 또는 **② 계정 네트워크 허용 목록에 Steam·SteamSpy 도메인 추가** 후 Claude 예약 작업. 명령과 도메인 목록은 `tools/game-crawler/README.md`.
- ✅ 📄 로컬 모의 테스트: `crawler.py --self-test`, `process.py --self-test` 통과(정렬·탈락·중복·신규 구분·미분류 태그).

## 8. 검증 상태와 한계
- ✅ 📄 `crawler.py --self-test`: 모의 응답으로 Wilson 정렬, 리뷰 수·비율 탈락, 평론가 병합, 불일치 판정, 파일 출력까지 통과.
- ⚠ 📄 **실제 API 미실행.** 확인 필요 지점은 코드의 `VERIFY` 주석: Steam 응답이 `response`로 감싸이는지, 리뷰 필드명·플레이타임 단위, SteamSpy `all`의 호출 제한(분당 1회로 기억), OpenCritic 호스트·필드명.
- ⚠ 🧠 Metacritic은 비공식 최선 노력(robots.txt 허용 시에만, 구조 변경·차단 시 `None`). **약관은 직접 확인**할 것.
- 🧠 SteamSpy 후보에는 DLC·소프트웨어가 섞일 수 있다. 결과를 보고 거르는 규칙을 추가해야 할 수 있다.

## 9. 다음 단계 (🧠 제안)
1. PC에서 `python tools/game-crawler/run_daily.py --limit 5`로 첫 실행 → 오류·필드명 보정(`VERIFY` 지점).
2. 결과 상위 1~2개 게임으로 `게임요소-사례-…` + 요소 페이지 1개를 샘플로 작성해 템플릿을 처음 시험([[개발-위시리스트-게임요소-라이브러리]] §6의 첫 단계).
3. 첫 정제 결과(`clean-날짜.md`)의 미분류 태그를 보고 `genre_map.json` 조정 → 요소 추출은 대화에서 10개 게임씩.
