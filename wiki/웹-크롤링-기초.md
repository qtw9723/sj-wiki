## 크롤링 방식 4가지

### 1. RSS + feedparser (현재 사용 중 ✅)
사이트가 새 글 목록을 XML로 공개하는 규격(RSS)을 feedparser 라이브러리로 읽는 방식.

```python
import feedparser, requests

response = requests.get("https://openai.com/blog/rss.xml")
feed = feedparser.parse(response.content)
for entry in feed.entries:
    print(entry.title, entry.link, entry.summary)
```

- **장점**: 빠름, 서버 부담 없음, 합법적, 코드 단순
- **단점**: RSS를 제공하는 사이트만 가능 (전체의 약 30~40%)
- **현재 수집 소스**: Anthropic, HuggingFace, OpenAI, Google DeepMind, Papers with Code, MIT AI

---

### 2. API (현재 사용 중 ✅)
사이트가 공식 데이터 API를 제공하면 JSON으로 바로 수신. [[카카오-Play-MCP]]의 NaverSearch가 이 방식.

```python
response = requests.get(
    "https://openapi.naver.com/v1/search/news.json",
    headers={"X-Naver-Client-Id": "...", "X-Naver-Client-Secret": "..."},
    params={"query": "LLM", "display": 10}
)
data = response.json()
for item in data["items"]:
    print(item["title"], item["link"])
```

- **장점**: 정형화된 JSON, 인증으로 안정적, 가장 깔끔
- **단점**: API를 제공하는 사이트만 가능, 키 발급 필요
- **현재 사용**: NaverSearch MCP가 API 키 관리까지 처리

---

### 3. HTML 파싱 — BeautifulSoup
RSS/API 없는 사이트에서 HTML을 직접 받아 CSS 선택자로 원하는 요소 추출.

```python
from bs4 import BeautifulSoup

response = requests.get("https://example.com/news")
soup = BeautifulSoup(response.text, "html.parser")

articles = soup.select("div.article-card h2 a")  # CSS 선택자
for a in articles:
    print(a.text, a["href"])
```

- **장점**: RSS 없는 사이트도 가능, 설치 간단 (`pip install beautifulsoup4`)
- **단점**: 사이트 구조가 바뀌면 선택자 수정 필요, JS 렌더링 불가

---

### 4. 브라우저 자동화 — Playwright / Selenium
JavaScript로 렌더링되는 사이트는 `requests`로 빈 HTML만 옴. 실제 브라우저를 코드로 조종.

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.goto("https://example.com")
    page.wait_for_selector(".article")       # JS 렌더링 완료 대기
    articles = page.query_selector_all(".article")
    for a in articles:
        print(a.inner_text())
    browser.close()
```

- **장점**: JS 사이트, 로그인 필요 사이트도 가능. 모든 사이트 대응
- **단점**: 느림, 무거움, 봇 탐지 우회 필요할 수 있음
- **🧠 연결점**: [[내-MCP-커넥터-환경]]의 `computer-use` / `Claude in Chrome`이 발상이 같음 — 브라우저를 코드로 제어하는 자동화

## ⚠ 수집·위키화 품질 규약 (2026-07-31 추가 — 실패 3건에서 도출)

> [!warning] 이 절은 "겪은 사고"에서 나온 규약이다
> 🧠 자동 수집·자동 위키화가 조용히 틀리는 방식이 3종 확인됐다. 결과물만 고치면 재발하므로(→ [[AI-주간-소식-2026-W31]] A 클러스터 *Living-Harness*: "하네스를 고치지 않으면 같은 실패가 재발") **규약으로 여기 남긴다.**

**① 롤링 피드 = 파일이 늘어도 새 항목은 일부** 📄
- RSS 크롤러는 피드 현재 상태를 그대로 저장하므로 **날짜별 파일 간 중복이 크다**. 실측: `2026-07-27`(15) + `07-28`(27) + `07-30`(29) + `07-31`(30) = **101건 → 유일 60건**(중복·재게시 41건). `2026-07-27.md` 15건은 **전량이 이미 [[AI-주간-소식-2026-W30]]에 반영**된 항목이었다.
- ✅ 규약: 위키화 전에 **기사 URL(arXiv는 ID·버전 무시) 단위로 중복 제거를 먼저** 하고, 그 결과를 건수로 쓴다. arXiv `v2/v3` 재게시는 같은 논문으로 센다.

**② 자동 위키화가 원본 항목 수를 대조하지 않는다** ⚠ 📄
- 2026-07-29 1차 패스 **14/28**, 2026-07-30 3차 패스 **12/28**, 2026-08-01 7차 패스 **8/30** — **3회 연속 대량 누락**. 페이지 자체는 그럴듯해 보여 눈으로는 안 걸린다.
- ✅ 규약: 자동 커밋(`auto(wiki)`) 뒤에는 **항상 수동 전수 대조 패스**를 붙인다. 대조는 제목이 아니라 **URL 식별자 단위**로 하고, 실무 접점이 없는 항목도 **한 줄 표로 전수 기록**해 추적 가능하게 남긴다(누락과 "의도적 낮은 우선순위"를 구분하기 위함).

**②-b 자동 위키화가 "쓰지 않은 항목"을 이력에 적는다** ⚠ 📄 *(2026-08-01 신규 — 규약 ② 위반의 더 나쁜 형태)*
- 📄 2026-08-01 7차 패스는 `log.md`와 페이지 보강 이력에 **"신규 12건 추가"**라고 적었지만, 본문에 실제로 작성된 항목은 **8건**이었다. **K-엑사원 2.0 · 미니맥스 H3 · 스몰리스트AI · AI 동맹의 시대**는 *이력 문장에만 이름이 있고 본문엔 없었다*.
- ⚠ 이게 ②보다 위험한 이유: **로그가 "완료"라고 말하므로 대조 자체를 건너뛰게 만든다.** 누락을 감추는 누락이다.
- ✅ 규약: 이력·`log.md`에 건수를 쓸 때는 **본문에서 해당 항목의 `###` 제목을 실제로 grep해 확인한 수**만 적는다. 이력에 이름을 나열했으면 그 이름이 본문에 있어야 한다.
- 🧠 근본 수정은 규약 문서가 아니라 **하네스**다(→ [[AI-주간-소식-2026-W31]] *Living-Harness*). `.wiki-sync.sh`의 위키화 프롬프트에 **"원본 항목을 URL 단위로 나열 → 각 항목의 반영 여부를 표로 자기점검 → 그 표의 ✅ 개수만 건수로 기록"** 단계를 넣는 것이 실제 고침. **미적용 상태**(2026-08-01 기준 TODO).

**③ 수집 공백이 조용히 생긴다** ⚠ 📄
- 📄 `2026-07-11.md` 다음이 곧바로 `2026-07-26.md` → **W29(7/13~7/19) 주간 페이지가 아예 없다**(크롤러 미실행 추정 🧠).
- 📄 `2026-07-28.md` 다음이 `2026-07-30.md` → **7/29 영문 수집 누락**(다만 롤링 피드라 7/30·7/31 파일이 7/29 발행분을 담아 실질 공백은 없었음).
- ✅ 규약: 위키화 시 **`raw/ai-digest/` 파일명 날짜 연속성을 먼저 확인**하고, 빠진 날은 주간 페이지에 `수집 공백` note로 명시한다(사후에 복구 불가한 정보이므로 숨기지 않는다).

## 추가 학습 포인트

- **robots.txt**: 사이트 루트의 `/robots.txt` — 크롤링 허용 여부 명시. 항상 확인하는 습관.
- **rate limiting**: 요청 간격 조절 (`time.sleep(1)`) — 서버에 부담 주지 않기 위함.
- **User-Agent**: `requests.get(..., headers={"User-Agent": "..."})` — 봇으로 차단 방지.
- **BeautifulSoup 설치**: `pip install beautifulsoup4`
- **Playwright 설치**: `pip install playwright && playwright install`
