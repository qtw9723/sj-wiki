> [!tip] 핵심 takeaway
> 🧠 이 페이지는 **읽고 바로 만들기 시작하는 문서**다. 나머지 악보-아카이브 문서가 "무엇을 왜"라면, 여기는 **"지금 무엇부터, 어떤 모양으로"**만 담는다.
> 📄 프로토타입은 박상준 단독 개발. 📄 저장소는 **신규 Supabase 프로젝트**(임시), 운영은 AWS 유력.
> 🧠 프로토타입의 목적은 기능 완성이 아니라 **검증 2건**이다 — ① 팀원이 카톡 대신 이 링크를 여는가 ② **iPad·갤럭시탭 양쪽에서** 펜 필기가 쓸만한가.

## 0. 이 문서를 읽는 개발 세션에게 (🧠)

- 배경·의사결정 근거가 필요하면 [[악보-아카이브]](마스터) → 필요한 주제 문서로 들어간다. **이 페이지만 보고도 착수는 가능**하다.
- 여기 적힌 것 **외의 기능은 만들지 않는다.** 범위를 넓히고 싶으면 먼저 [[악보-아카이브]] §MVP 범위와 대조한다.
- 📄/🧠 표기: 📄는 사용자가 확정한 것, 🧠는 판단/제안이다. **📄를 임의로 바꾸지 않는다.**

## 1. 목표와 비목표

### 목표 (이것만 된다면 성공) 🧠
1. 팀장이 악보 몇 개를 골라 **세트를 만들고 링크를 얻는다.**
2. 그 링크를 폰/패드에서 열면 **악보가 순서대로 보인다.**
3. 악보 위에 **필기가 되고, 다시 열었을 때 남아 있다.** — 📄 iPad·갤럭시탭 **양쪽 모두**

### 비목표 (프로토타입에서 만들지 않는다) 🧠
- 로그인 — 📄 하드코딩 사용자 1명으로 시작
- 악보 등록 UI — Supabase 대시보드 직접 업로드로 대체
- OCR·가사 추출·조옮김 · 검색 UI · 오프라인 캐싱 · 멀티팀 UI · 병합 PDF 다운로드
- 권한 검사(RLS) — §5 참조

> [!warning] 🧠 비목표를 만들고 싶어지면
> 그 기능이 위 검증 2건 중 하나에 직접 기여하는지 자문한다. 아니면 [[악보-아카이브]] Phase 1로 미룬다.

## 2. 반드시 지킬 규약 2가지 (🧠 — 소급 적용이 가장 아픈 것)

1. **`team_id`** — 팀에 귀속되는 모든 테이블에 넣는다. 프로토타입에서 UI에 노출하지 않아도 **컬럼과 값은 넣는다.** (근거: [[악보-아카이브-인증-권한]] §4)
2. **`storage_path`** — DB에는 전체 URL이 아니라 상대 경로만 저장한다. (근거: [[악보-아카이브-데이터-모델]] §1-2)

## 3. 초기 스키마 (🧠 초안 — 그대로 실행 가능)

> [!note] 적용 방법
> 🧠 신규 Supabase 프로젝트이므로 **`supabase/migrations/`에 파일로 두고 `supabase db push`** 를 표준으로 한다. ⚠️ [[parking]]·[[mailer]]의 정책 충돌과 무관한 별도 프로젝트다(→ [[악보-아카이브-데이터-모델]] §1-1). 아래 SQL은 멱등하게 작성돼 재실행해도 안전하다.

```sql
-- ============================================
-- 악보 아카이브 프로토타입 초기 스키마
-- ============================================
create extension if not exists "pgcrypto";

-- 팀 -----------------------------------------
create table if not exists teams (
  id          uuid primary key default gen_random_uuid(),
  name        text not null,
  created_at  timestamptz not null default now()
);

-- 사용자 (자체 users가 정본. Supabase auth.users에 의존하지 않는다) ---
-- 근거: 악보-아카이브-인증-권한 §3-3 (AWS 이전 시 Auth가 유일한 락인)
create table if not exists users (
  id             uuid primary key default gen_random_uuid(),
  auth_provider  text not null default 'local',   -- 'kakao' | 'local'
  provider_uid   text,                            -- 카카오 회원번호 등
  display_name   text not null,                   -- 카톡 닉네임과 별개로 관리
  created_at     timestamptz not null default now(),
  unique (auth_provider, provider_uid)
);

-- 멤버십 (users는 team_id를 갖지 않는다 — 겸직 대비) ---
create table if not exists memberships (
  user_id    uuid not null references users(id) on delete cascade,
  team_id    uuid not null references teams(id) on delete cascade,
  role       text not null default 'member',      -- 'leader' | 'member' | 'admin'
  status     text not null default 'active',      -- 'active' | 'pending'
  created_at timestamptz not null default now(),
  primary key (user_id, team_id)
);

-- 악보(곡) -----------------------------------
create table if not exists sheets (
  id                   uuid primary key default gen_random_uuid(),
  team_id              uuid not null references teams(id) on delete cascade,
  title                text not null,
  composer             text,
  key                  text,
  tags                 text[] not null default '{}',
  lyrics_text          text,                       -- Phase 3 검색용. 지금은 비워둠
  original_path        text,                       -- 상대 경로만! 전체 URL 금지
  normalized_pdf_path  text not null,              -- 뷰어가 쓰는 정규화 PDF
  page_count           int  not null default 1,
  created_by           uuid references users(id),
  created_at           timestamptz not null default now(),
  updated_at           timestamptz not null default now()
);
create index if not exists sheets_team_idx on sheets(team_id);

-- 세트(예배 곡목) ----------------------------
create table if not exists sets (
  id           uuid primary key default gen_random_uuid(),
  team_id      uuid not null references teams(id) on delete cascade,
  title        text not null,
  service_date date,
  share_token  uuid not null default gen_random_uuid(),  -- 링크 배포용. 추측 불가
  note         text,
  created_by   uuid references users(id),
  created_at   timestamptz not null default now()
);
create unique index if not exists sets_share_token_idx on sets(share_token);
create index if not exists sets_team_date_idx on sets(team_id, service_date desc);

-- 세트 안의 곡 순서 --------------------------
create table if not exists set_items (
  id                 uuid primary key default gen_random_uuid(),
  set_id             uuid not null references sets(id) on delete cascade,
  sheet_id           uuid not null references sheets(id) on delete restrict,
  position           int  not null,
  key_override       text,
  song_form_override text,
  item_note          text,
  unique (set_id, position)
);
create index if not exists set_items_set_idx on set_items(set_id, position);

-- 메모 (append-only. 수정 없음, 추가만) --------
-- 근거: 악보-아카이브-메모-동기화 §3
create table if not exists annotations (
  id          uuid primary key,          -- ⚠️ 서버 기본값 없음. 클라이언트가 UUID 생성
  sheet_id    uuid not null references sheets(id) on delete cascade,  -- 세트 아님!
  team_id     uuid not null references teams(id) on delete cascade,
  user_id     uuid not null references users(id) on delete cascade,
  page        int  not null,
  layer       text not null default 'personal',   -- 'personal' | 'shared'
  kind        text not null default 'ink',        -- 'ink' | 'text' | 'song_form'
  payload     jsonb not null,                     -- 좌표는 0~1 상대값!
  deleted     boolean not null default false,     -- 지우개도 추가다
  created_at  timestamptz not null default now(),
  synced_at   timestamptz not null default now()
);
create index if not exists annotations_lookup_idx
  on annotations(sheet_id, user_id, layer, page);
```

### 스키마에서 놓치면 안 되는 3가지 (🧠)
1. `annotations.id`에 **`default gen_random_uuid()`를 두지 않았다.** 오프라인 클라이언트가 직접 발급해야 재전송이 멱등해진다.
2. `annotations.sheet_id`는 **`set_id`가 아니다.** 이게 "같은 곡이면 필기가 따라온다"(📄 D1)의 전부다.
3. `payload`의 좌표는 **0~1 상대값**. 절대 픽셀로 저장하면 화면 크기가 다른 기기에서 어긋난다.

## 4. Storage 구조와 모듈 계약 (🧠)

**버킷**: `sheets` (비공개). 공개 버킷으로 열지 않는다.

```
sheets/{sheet_id}/original.{ext}      -- 업로드 원본 (보존, 수정 안 함)
sheets/{sheet_id}/normalized.pdf      -- 뷰어가 쓰는 PDF
sheets/{sheet_id}/thumb.png           -- 목록용 (선택)
```

**모듈 계약** — 파일 접근은 반드시 이 한 모듈만 거친다. Supabase 클라이언트를 UI 컴포넌트에서 직접 부르지 않는다.

```ts
// storage.ts — AWS 전환 시 이 파일 하나만 바꾸면 되도록 유지할 것
export interface SheetStorage {
  upload(sheetId: string, file: File, kind: 'original' | 'normalized'): Promise<string>; // → storage_path 반환
  getSignedUrl(storagePath: string, expiresInSec?: number): Promise<string>;
  remove(storagePath: string): Promise<void>;
}
```

- 🧠 DB에는 `getSignedUrl`이 만든 URL이 아니라 **`storage_path` 문자열만** 저장한다. 서명 URL은 매번 발급한다(만료되므로).

## 5. 권한(RLS) — 프로토타입 방침 (🧠)

- 프로토타입은 **RLS를 켜지 않는다.** 사용자가 1명(하드코딩)이라 정책을 검증할 대상이 없고, 개발 속도만 깎는다.
- ⚠️ 대신 **Phase 1 진입 시 반드시 켠다.** 그때 정책은 전부 `team_id` 기준으로 건다(→ [[악보-아카이브-인증-권한]] §4-1). 나중에 거는 게 훨씬 번거로우니 **Phase 1 첫 작업으로** 잡는다.
- ⚠️ 프로토타입 기간에는 **anon key로 데이터가 열려 있다**는 뜻이다. 실제 교회 데이터나 저작권 있는 악보를 대량으로 넣지 않는다. 테스트용 소수만.

## 6. 화면 3개 (🧠 — 이것만 만든다)

| 화면 | 경로 | 내용 |
|---|---|---|
| 세트 목록 | `/sets` | 세트 나열 + 새 세트 만들기 |
| 세트 편집 | `/sets/:id/edit` | 악보 골라 담기, 순서 조정, **링크 복사** |
| 뷰어 | `/s/:shareToken` | 📄 배포되는 링크. 악보 순서대로 표시 + 필기 |

뷰어에 필요한 최소 기능 (🧠, 상세는 [[악보-아카이브-뷰어-배포]] §4):
- 좌우 절반 탭으로 페이지 넘김 (예배 중 정확한 탭이 어렵다)
- 곡 간 이동
- **화면 꺼짐 방지(Wake Lock)** — ⚠️ 없으면 예배 중 화면이 꺼진다. 놓치기 쉬운 필수 항목
- 펜 필기 (Pointer Events, 필압) — ⚠️ **팜 리젝션(`pointerType==='pen'` 필터 + `touch-action:none`)과 `getCoalescedEvents()`는 필수**. 상세 → [[악보-아카이브-필기-크로스플랫폼]] §2

## 8. 하지 말 것 (🧠)

- ❌ Supabase **Realtime** 사용 — AWS 대응물이 애매하고, 지금 실시간이 필요한 지점이 없다
- ❌ `auth.users`에 직접 조인 — 자체 `users`가 정본
- ❌ DB에 전체 URL 저장
- ❌ 필기를 이미지 한 장으로 저장 — 반드시 스트로크 단위
- ❌ 좌표를 절대 픽셀로 저장
- ❌ **플랫폼별 필기 분기 코드** — Pointer Events 한 벌로 양쪽을 커버한다
- ❌ **백그라운드 동기화(Background Sync) 의존** — iOS에 없다. 포그라운드 복귀 시 처리로 통일
- ❌ 과도한 추상화 레이어 — §4 모듈 하나면 충분하다

## 9. 완료 정의 (🧠)

프로토타입은 **아래 두 문장에 답이 나오면 끝난다.** 기능이 남았어도 끝낸다.

1. "카톡에 링크를 던졌을 때 팀원들이 여는가? 여는 데 걸림돌은 무엇이었나?"
2. "iPad·갤럭시탭 펜 필기가 예배에서 쓸 만한가? 한쪽만 아쉽다면 어느 쪽이 무엇이 부족한가?"

→ 답을 [[악보-아카이브]]에 기록하고 Phase 1 범위를 확정한다.

## 9-1. 규약 준수 자체점검 (🧠 **정수로 답한다**)

> [!warning] 왜 서술형으로 쓰지 않는가
> 🧠 이 vault에서 실측으로 확인된 것이다 — 📄 [[AI-주간-소식-2026-W35]] §11차 ①: 점검 칸이 서술·부등호(`>0`)를 허용하면 **세 패스 연속으로 거짓이 통과했고**, 같은 점검표에서 **정수를 적은 칸은 한 번도 거짓이 아니었다**. 🧠 규약(`team_id`·`storage_path`)은 소급 적용이 가장 아픈 두 가지라, 프로토타입 단계에서 **정수 카운터**로 확인해 둔다.

프로토타입 종료 시 아래를 **숫자로** 채운다. `✅`·`확인함`·`>0` 은 미기재로 간주한다.

- `team_id 컬럼이 없는 테이블 = ___ 개` (teams 자체 제외 → **0**)
- `storage_path 없이 올라간 파일 = ___ 개` (**0**)
- `서버 기본값(`gen_random_uuid()`)이 붙은 `annotations.id` = ___ 개` (**0** — 클라이언트 UUID 발급 유지)
- `절대 픽셀 좌표로 저장된 스트로크 = ___ 건` (**0** — 좌표는 0~1 상대값)
- `RLS 미적용 테이블 = ___ 개` (프로토타입 기간엔 0이 아니어도 되지만, **Phase 1 첫 작업에서 0**으로 만든다)
- `프로토타입 버킷에 올린 저작권 악보·실명 데이터 = ___ 건` (**0** — RLS 없는 기간엔 금지. 🧠 (KR-W35-68) *코딩 도구가 기업 코드를 외부 전송* 사례와 같은 구조의 리스크다: *"임시니까 괜찮다"* 가 실데이터를 만나는 순간 사고가 된다)
- `iPad·갤럭시탭 실기 테스트 미실시 항목 = ___ 개` ([[악보-아카이브-필기-크로스플랫폼]] 테스트 매트릭스 기준)
