> [!tip] 핵심 takeaway
> 📄 엑셀 표를 RAG 문서 저장소(docstore)에 올렸을 때 **헤더가 같은 표가 여러 개면, 표 위 제목·설명 한 줄이 있느냐가 검색 성공을 통째로 가른다**(제목 있음 15/15, 제목 없음 0/15).
> 🧠 청크 크기·표 복원 같은 엔진 설정보다 **문서를 어떻게 쓰느냐(제목·설명·세로 배치)**가 먼저다. 이 결과를 고객용 "문서 작성 가이드"로 바꾼 것이 실무 성과.

## 배경 📄
- 사내 RAG 문서 저장소(docstore)에 보험 상품 문서(인도네시아어·영어, 엑셀 43 + PDF·TXT 51 = 94개)를 올렸더니 **표 안 값**을 묻는 질문이 잘 안 잡혔다.
- 청크 설정만 다른 저장소 여러 개에 같은 질문을 던져 정답 청크 순위를 비교하는 도구 [[rag-compare]]를 셋업해 테스트를 시작했다.
- 고객 실데이터(요율 값·저장소 ID·키)는 이 페이지에 넣지 않는다. 상세는 회사 vault.

## 진행 단계

### 1단계. 청크 설정 비교 (10-14) 📄
- 비교 저장소 5개: 고정 청크 6000 / 임의 청크 1200 / 1200 + 표 3배 청킹 / 1200 + 표검색 개선 / 700 + 표검색 개선. 파라미터 `topn 10`, `score 0.1`, `restore_table true`.
- 질의 5개(특정 나이의 요율, 직업 등급 등 표 안 값). 저장소별 MRR·1위 정답 수 결과 수치는 남아 있지 않다.

### 2단계. 테스트 문서 재가공 (10-19 ~ 10-21) 📄
- **한국어 정리본**: 94개 파일·표 443개를 파일별·표별로 정리(서브에이전트 9개 병렬). 원본과 안 맞는 곳 250개 표시. ⚠ 큰 요율표는 샘플만 넣어서 **검색 정답 기준으로 쓰면 안 된다** → 정답 문구는 저장소에 올린 파일 기준으로 잡는다.
- **원어 제목 청크본**: docstore가 제목마다 자르는 점을 이용해 `## {파일명} — {섹션/표}` 형식으로 다시 씀. 규칙은 SPEC 하나로 고정(번역 금지, 표 행 생략 금지, `##`만 사용, 본문 300~1,500자). 최종판은 **표 하나 = 청크 하나**, 1,649청크.
- **표 카탈로그**: 표 473개에 인니어+영어 제목·설명·키워드·예상 질문·샘플 행을 붙여 질문→표 매칭용으로 따로 임베딩. 본문 청크와는 제목으로 연결.
- 10-21: 일부 표(52개)의 청크 제목을 UUID로 바꾸고 표-UUID 매핑표를 만든 실험(원본은 백업).
- 같은 기간 [[rag-compare]]에 "정답 문구 여러 개면 또는", "한 문서 기준 검색" 옵션 추가. 정답이 여러 청크에 나뉜 경우의 조각 판정은 넣었다가 되돌림.

### 3단계. 통제된 표 검색 샘플 (10-23 ~ 11-03) 📄
- 실데이터 대신 **가상 회사 2곳**(원두 도매상, 식물 농원)의 엑셀을 직접 만들어 변수를 통제. 시트 분리판(10-23) → 한 시트 여러 표 v1(10-26) → v2(11-03, 생성 스크립트로 재생성).
- v2 핵심 장치: **헤더가 똑같은 표 여러 개**(배송비 표 4종, 온실 기록 4곳, 연도별 발아 시험 3년), 긴 표, 정답이 표 위 설명 줄에만 있는 항목.
- 같은 내용을 4가지 형태로 저장: 제목·설명 있음/없음 × 표 가로 나란히/세로.
- 질문 세트(영어·한국어 쌍, rag-compare용 JSON): 기본 15, 어려운 14, 복합의도 14, 복합의도-어려운 14(돌려 말하기·집계·연쇄), v2 새 표 12, 제목 의존 10, 문서 복합 7.
- 판정 기준: **찾음** / **실패(표 구분 불가)** = 값 있는 표는 나왔지만 같은 헤더 표 중 어느 것인지 모름 / **실패(청크 없음)**.

## 결과 (제목 의존 5문항, 11-03) 📄

| 질문 유형 | 제목 있음 (가로·세로) | 제목 없음 (가로·세로) |
|---|---|---|
| 같은 헤더 배송비 표 4개 동시 | 4/4 | 0/4 표 구분 불가 |
| 같은 형식 온실 기록 3개 구분 | 3/3 | 0/3 표 구분 불가 |
| 연도를 돌려 말하기("작년", "올해") | 3/3 | 0/3 표 구분 불가 |
| 정답이 설명 문장에만 있음 | 3/3 | 0/3 **청크 없음** |
| 표 전체 최솟값·최댓값 | 2/2 | 0/2 표 구분 불가 |
| **합계** | **15/15** | **0/15** |

- 가로·세로 배치는 정답 수 차이 없음. 다만 **가로 배치는 같은 엑셀 행에 있는 옆 표가 한 청크로 묶여** 질문과 무관한 표(로스팅 일정, 포장 옵션 등)가 같이 올라왔다.

## 배운 점 🧠
- 같은 헤더 표가 여럿이면 **제목이 유일한 구분 단서**다. 임베딩도 LLM도 제목 없이 표를 구분할 근거가 없다.
- 단위·기간·마감 시각·용도처럼 셀에 없는 정보는 **설명 줄이 없으면 검색할 텍스트 자체가 없다**. 이때 답이 나오면 할루시네이션이다.
- 가로 배치 문제는 청커가 엑셀을 행 단위로 읽기 때문이다. 문서 쪽 해결(세로 배치, 표 사이 빈 행)이 엔진 수정보다 싸다.
- 실데이터 테스트는 정답 기준이 흔들리기 쉽다(정리본 vs 올린 파일). **가상 데이터로 변수 하나씩 통제한 샘플**이 결론을 훨씬 분명하게 냈다.

## 산출물 📄
- 고객 전달용 결과 문서: 4형태 비교표 + **문서 작성 가이드**(표마다 제목 1줄, 제목에 구분 기준(종류·대상·연도), 설명 1줄에 셀에 없는 정보, 제목·설명은 표 바로 위, 표는 세로 배치, 표 사이 빈 행 1~2줄).
- 질문·정답 md(영/한), rag-compare 테스트셋 JSON, v2 엑셀 생성 스크립트.

## 남은 일 / 이슈 📄
- 사용자가 4개 저장소에 v2 재업로드 후 테스트(11-03 기준 후속).
- 비슷한 이름의 세 번째 회사 파일(혼동 유도)은 기존 질문이 모호해져 보류.
- 검색 쪽 코드가 query를 덮어써서 질의와 청크가 안 맞는 경우가 있다(확인 필요).
