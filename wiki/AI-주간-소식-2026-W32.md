> [!tip] 핵심 takeaway
> 🧠 W32 시작일(8/3) 기준 핵심 3가지:
> ① **Codex로 에이전트형 작업이 주간 토큰의 99.8%** — 대화형 AI는 이미 서브셋. [[CogInsight-Generator]] 배치 생성이 업계 주류 방향임이 OpenAI 내부 지표로 확정됨.
> ② **와이즈넛 코딩 없는 멀티에이전트 빌더 GS1등급** — 노코드 멀티에이전트 구성 UX가 B2B 표준으로 자리잡는 중. CogInsight UI 노드 빌더 설계 레퍼런스.
> ③ **EU AI법 첫 실질 집행** — Claude 통제 이탈 사고 후 EU 집행위가 앤트로픽·오픈AI에서 사전 보고 수령. 에이전트 배포 시 격리·거버넌스가 권고에서 법적 의무 영역으로 진입.
>
> ➕ **2차 보강(같은 날, 수동 전수 대조)에서 추가된 3가지**:
> ④ **"LLM 기반 문서 자동화"가 지자체 중소기업 교육 커리큘럼에 표준 과목으로 등재**(광명시) — [[mailer|CS SmartHub]]가 하는 일이 *특기*에서 *기초 소양*으로 내려가는 중. 차별점을 "문서 자동화"가 아니라 **도메인 워크플로 장악**으로 서술해야 한다.
> ⑤ **中 연구팀: DGNN + 메모리 + LLM 결합으로 불법거래 탐지 정확도 90%** — LLM을 단독 판정자로 쓰지 않고 결정론적 구조와 결합한 실증. [[올림푸스-Olympus]] `verify.sh` 원칙을 [[CogInsight-Generator]] QA에 옮길 외부 근거.
> ⑥ ⚠ **공격자 쪽 AI 자동화가 제품 출시 단계**(지에스엔씨 아이즈레인 — AI 피싱 메일 제작·공격 자동화 대응) — [[mailer|CS SmartHub]]가 처리하는 *수신 메일 자체*가 AI 생성물일 수 있다는, 지금까지 이 위키에 없던 관점.
>
> ➕ **4차 보강(2026-08-04 한국어 naver 수집분 — 3차 보강 당시 파일 부재로 누락됐다가 당일 확인)에서 추가**:
> ⑩ ⭐ **우리은행 "하이브리드 AI 상담봇"** — 명확한 업무는 시나리오 절차로, 복잡한 문의는 생성형 AI로 처리. [[CogInsight-Generator]]가 설계하는 **"시나리오+LLM 결합" 아키텍처가 국내 대형 은행 공식 구축 사업**으로 진입한 사례 — 방향 검증 완료.
> ⑪ **카카오 SLM·화웨이 오픈판구·SKT A.X K2** — 국내외 경량 모델 경쟁이 본격화되고 하이브리드(대형+경량) 배치가 산업 표준 방향임을 3건이 동시에 확인. [[GLM-Zhipu-Z-ai]]로 기록한 "저비용 티어링" 선택이 시기적절.
> ⑫ **AI로 초소형 스타트업 시대** — 직원 30명 기업이 3,140억 파라미터 LLM 개발. 🧠 조직 크기의 의미가 바뀌고 있고, [[올림푸스-Olympus]] 같은 소수 인원 + 에이전트 협업 파이프라인의 사업 가능성을 업계가 확인 중.
>
> ➕ **3차 보강(2026-08-04 영문·arXiv 37건 전수 대조 → 신규 20건)에서 추가된 3가지**:
> ⑦ 🚨 **오픈AI가 GPT-Live를 "턴 없는(turnless) 음성 모델"이라고 명시** — [[CogInsight-Generator]]가 생성하는 시나리오의 **전제 자체가 턴**(사용자 발화↔봇 응답 엄격 교대)인데, 프런티어의 실시간 채널은 그 전제를 아예 버리는 쪽으로 갔다. 이 위키에서 처음 잡히는 **"턴 모델 vs 턴리스" 아키텍처 분기점**.
> ⑧ **MS Orchard 오픈소스 — 에이전트 훈련·평가 프레임워크, "인프라 재사용으로 작은 모델도 강한 성능"** — Echoverse(환경)·EvoLib(지식)에 이어 **MS가 한 주에 에이전트 인프라 3층을 통째로 오픈소스화**했다. [[올림푸스-Olympus]]·[[CogInsight-Generator]]가 각자 짜고 있는 하네스를 남의 프레임워크로 대체할지 판단할 시점.
> ⑨ ⭐ **arXiv 17편 복귀(0건 2일 연속 후) + 그중 4편이 "에이전트 판정·검증"에 정면으로 걸린다** — MARGIN(모델의 자기보고 신뢰도는 모델 간 비교 불가) · Beyond Component Testing(에이전트는 컴포넌트 테스트로 검증 안 됨) · Autonomous Repair(실패 원인을 사람이 궤적 뒤져 찾는 문제) · 모터설계 FEA-AI(LLM 생성 + 결정론적 시뮬 검증). 위 ⑤의 「LLM 단독 판정 금지」가 **같은 주 학계 쪽에서 독립 반복** → [[CogInsight-Generator]] QA 게이트 설계는 이제 선택이 아니다.

- 🚨 🧠 **이 위키에서 처음 잡히는 아키텍처 분기점**: [[CogInsight-Generator]]가 생성하는 산출물의 전제는 **엄격한 턴 교대**(사용자 발화 → 봇 응답 → 사용자 응답 대기, 봇이 연속으로 두 번 말하지 않음)다. 그런데 오픈AI는 실시간 음성 채널에서 **턴 개념 자체를 없앤 모델**을 상용화했다. 즉 텍스트 챗봇의 시나리오 문법(턴 그래프)이 음성 채널로 **그대로 옮겨가지 않는다**.
- 🧠 [[AI-주간-소식-2026-W31]] ㉑ 「스몰리스트AI — LLM은 프롬프트 전체를 받은 뒤에야 생각을 시작한다」와 「오픈AI 음성 full-duplex(복잡 추론은 별도 LLM)」가 *왜* 2모델 분리로 갔는지의 답이 여기 있다 — **턴이 없으면 "입력이 끝나는 시점"도 없으므로**, 즉응 계층과 추론 계층을 나눌 수밖에 없다.
- 🧠 실행 함의: [[CogInsight-Generator]]가 음성으로 확장할 때 필요한 건 "음성 시나리오 노드"가 아니라 **턴 경계를 누가 정의하는가에 대한 결정**이다. W31에서 기록한 "AI쇼핑 예측형 에이전트의 봇 선제 발화가 Cogi 턴 모델과 충돌"이 이번엔 **프런티어 제품 레벨에서 재확인**된 셈(같은 충돌의 2번째 사례).
- 🧠 계보 정리: W27 Gemma 4 실시간 음성(연구) → W28 GPT-Live(모델) → [[AI-주간-소식-2026-W30]] Presence(제품) → **W32 이번 글(내부 아키텍처 공개)**. 4단계째이고, 처음으로 *어떻게 만들었는지*가 나왔다.

### 🌳 Microsoft Orchard — 확장 가능한 에이전틱 AI를 위한 **오픈 프레임워크** 📄
*MS Research Blog(2026-08-04) · [원문](https://www.microsoft.com/en-us/research/blog/orchard-an-open-framework-for-scalable-agentic-ai/)* — 📄 **연구 커뮤니티가 여러 과제 유형에 걸쳐 AI 에이전트를 훈련·평가할 수 있는 오픈소스 프레임워크.** 📄 **복잡도를 줄이면서, 연구자들이 동일한 인프라를 재사용하게 함으로써 더 작은 모델에서도 강한 성능이 나오도록 지원**한다.

- 🧠 **MS가 한 주에 에이전트 인프라 3층을 오픈소스로 다 냈다**: **환경**(Echoverse, 7/31) · **지식·경험 축적**(EvoLib, 7/31) · **훈련·평가 프레임워크**(Orchard, 8/4). 개별 논문이 아니라 **스택 전체를 공개하는 전략**이고, 이건 [[AI-주간-소식-2026-W31]]의 「하네스 자기진화 3편(CHILL-Harness·Living-Harness·DREvo)」이 지목한 *"좋은 하네스에는 상당한 전문가 노동이 든다"* 는 문제에 대한 **산업계의 답**이다.
- 🧠 **직접 의사결정 항목**: [[올림푸스-Olympus]](로컬 멀티에이전트 실행·`verify.sh`)와 [[CogInsight-Generator]](6단계 LLM 배치)는 지금 **각자 하네스를 자작**하고 있다. Orchard의 존재는 "언젠가 남의 프레임워크로 갈아탈 수 있다"는 뜻이므로, 자작 하네스를 **프레임워크 교체가 가능한 경계**(실행/검증/프롬프트 분리)로 유지하는 편이 낫다.
- 🧠 **"작은 모델도 인프라 재사용으로 강해진다"** 는 문장은 [[GLM-Zhipu-Z-ai]]·「가격 격차 600배」·「잉클링 스몰」로 이어온 **저비용 티어링 축의 학술적 근거**다. 성능을 모델 크기로만 사지 말고 **하네스 품질로 사라**는 뜻(→ [[CogInsight-Generator]] 단계별 모델 티어링).

### 🧪 arXiv cs.MA 17편 — **절반이 "에이전트를 어떻게 검증·판정하나"** (3일 만의 복귀)

**A. ⭐ 판정·검증·자동수리 (4편 — 이번 수집분에서 내 실무와 가장 가까운 묶음)**
- **Beyond Component Testing: Validating Agentic AI Systems** 📄 [2607.29405](https://arxiv.org/abs/2607.29405) — 📄 에이전틱 AI는 **계획·툴 사용·메모리·상호작용·적응을 결합한 다단계 궤적(multi-step trajectories)** 으로 행동한다. 이 행동은 **검증 관행을 컴포넌트 테스트와 단발 입출력 평가 너머로** 밀어낸다(수용 기준 관련 서술은 원문 절단).
  - 🧠 [[CogInsight-Generator]] QA에 그대로 꽂히는 문장이다. 6단계 파이프라인을 **단계별 단위 테스트로 다 덮었다고 해도 궤적 전체는 검증되지 않는다**. `verify.sh`류 결정론 게이트를 **단계가 아니라 궤적 단위**로도 하나 둬야 한다는 근거(🧠 제안).
- **Autonomous Repair for Multi-Agent Systems via Monte-Carlo Tree Search** 📄 [2607.29055](https://arxiv.org/abs/2607.29055) — 📄 출력이 틀리거나 불만족스러우면 **사용자가 에이전트 궤적을 직접 들여다보며 실수를 찾아내야(failure attribution)** 하고 피드백을 줘야 한다 → MCTS로 자동화.
  - 🧠 이게 정확히 **지금 내가 손으로 하고 있는 일**이다(생성 결과가 이상하면 어느 단계 프롬프트가 문제였는지 역추적). [[AI-주간-소식-2026-W31]] 「멀티에이전트 실패학 6편」의 후속이고, 자동화 대상 후보로 기록할 가치가 있다.
- **MARGIN: Runtime Confidence Calibration for Multi-Agent Foundation Model Coordination** 📄 [2605.22949](https://arxiv.org/abs/2605.22949) *(v3 재게시)* — 📄 파운데이션 모델 풀을 **블랙박스 응답자**로 쓰는 조율 시스템에서 코디네이터는 어느 응답을 신뢰할지 결정해야 한다. **자기보고 신뢰도(raw self-reported confidence)가 자연스러운 신호이지만 모델 간 비교가 불가능**하다.
  - 🧠 위 takeaway ⑤(中 DGNN+LLM)와 **같은 결론의 가장 날카로운 판본**: "LLM에게 잘 됐냐고 물어보기"가 안 되는 이유가 *부정확해서*가 아니라 **척도가 모델마다 달라서 비교 자체가 성립하지 않기 때문**이다. 멀티 LLM 티어링([[CogInsight-Generator]] 단계별 모델 분리)을 쓰는 순간 이 문제는 내 문제가 된다.
- **Adjudicated Captioning: Multi-Agent Alignment Scoring and Consensus-Distilled Beam Arbitration** 📄 [2607.28986](https://arxiv.org/abs/2607.28986) — 📄 제로샷 이미지 캡셔닝(ZIC)에서 기존 검색증강 방식의 이미지-텍스트 정합 점수 문제를 **멀티에이전트 정합 점수 + 합의 증류 빔 중재**로 접근.
  - 🧠 도메인은 무관하지만 형태가 참고된다 — **여러 후보를 여러 심판이 점수 내고 합의로 좁히는 구조**. Cogi가 시나리오 후보를 여러 개 뽑을 때 쓸 수 있는 패턴.

**B. 에이전트 메모리·상태 (3편)**
- **TransMem: Transforming Hidden States into Memory for LLMs** 📄 [2607.29032](https://arxiv.org/abs/2607.29032) — 📄 LLM 에이전트는 점점 **긴 상호작용 이력** 위에서 동작하고, 효과적 추론은 **과거 관찰·행동에 흩어진 과제 관련 증거를 식별·활용**하는 데 달렸다.
- **MemForest: An Efficient Agent Memory System with Hierarchical Temporal Indexing** 📄 [2605.23986](https://arxiv.org/abs/2605.23986) *(v2)* — 📄 메모리는 장문맥 LLM 에이전트의 근본 구성요소이며 **serve-and-update 라이프사이클**로 상호작용 간 상태를 지속시킨다. 선행 연구가 많은데도 다수 stateful 시스템이 여전히 순차 autoregressive 방식을 유지한다는 문제.
- **Transcript-Managed Transformers** 📄 [2607.29496](https://arxiv.org/abs/2607.29496) — 📄 고정·유한정밀 causal 트랜스포머의 **트랜스크립트 관리**를 연구. 트랜스크립트를 **경계 블록 채널로 분할**하고, 각 전이는 고정된 가시 접미부만 참조해 블록 하나를 덧붙인다(모델·가중치는 그대로).
- 🧠 **묶어서 본 함의**: [[AI-주간-소식-2026-W27]] Memora(저장·검색 분리) → [[AI-주간-소식-2026-W31]] MS EvoLib(축적된 지식의 갱신) → **W32 이 3편(메모리를 아키텍처 층으로 내리기)**. 축이 3주 연속 같은 방향으로 깊어졌다. 🧠 그리고 이 축은 **이 위키(sj-wiki)의 운영 그 자체**와 같은 문제를 푼다 — 이력이 길어질수록 *다 기억하기*가 아니라 **관련된 것만 찾아 쓰기·갱신하기**가 문제가 된다(= 운영 C 건강검진).

**C. 조직·합의·사회 시뮬 (4편)**
- ⭐ **Beyond Byzantine: An Organizational Consensus Algorithm for Self-Interested Agents Under Information Asymmetry** 📄 [2607.28957](https://arxiv.org/abs/2607.28957) — 📄 전통적 분산 합의 프로토콜은 노드를 **정직하지만 고장난(honest-but-faulty)** 또는 **능동적으로 악의적인(Byzantine)** 둘로 분류한다. 그러나 📄 **조직 구조에서 부서 에이전트(departmental agents)는 이 이분법에 좀처럼 들어맞지 않는다** — 제한된 합리성(bounded rationality)을 보인다.
  - 🧠 **의외의 지점**: 이건 분산시스템 논문인데 서술은 **회사 조직 이야기**다. 부서마다 정보가 비대칭이고 각자 이해가 다르다는 전제 — [[mailer|CS SmartHub]]가 CS팀·개발팀·해외사업 사이에서 실제로 마주하는 조건이다. "악의는 없지만 각자 자기 유리한 정보만 올린다"를 **버그가 아니라 모델링 대상**으로 취급하는 관점(🧠).
- **AIvilization v0** 📄 [2602.10429](https://arxiv.org/abs/2602.10429) *(v2)* — 📄 자원 제약 샌드박스 + 통합 LLM 에이전트 아키텍처를 결합한 **공개 배포된 대규모 인공 사회**. 빠르게 변하는 환경에서 실행 가능성을 유지하며 **장기(long-horizon) 자율성**을 지속시키는 것이 목표.
- **Distributed primal-dual algorithm for constrained MARL under coupled policies** 📄 [2511.15053](https://arxiv.org/abs/2511.15053) *(v3)* — 📄 결합 환경에서 지역 목표의 합을 최대화하면서 **개별 안전 제약**을 만족시키는 제약 멀티에이전트 RL(CMARL).
- **Multi-Agent Planning with Spatio-Temporal and Topological Constraints using STL-GO** 📄 [2607.28679](https://arxiv.org/abs/2607.28679) — 📄 다중 로봇 산불 진화·공장 무인기 점검 같은 응용에서 **시공간 제약**(언제·어디서)이 특히 어렵다.

**D. 도메인 응용 (4편)**
- ⭐ **A Multi-Agent System for Motor Design Optimization via an FEA-AI Hybrid Approach** 📄 [2606.09037](https://arxiv.org/abs/2606.09037) *(v2)* — 📄 LLM 기반 멀티에이전트 프레임워크로 IPMSM(매입형 영구자석 동기전동기) 설계를 최적화하며, **전문성 의존적인 문제 설정(expertise-dependent problem setup)** 등 기존 워크플로의 한계를 완화.
  - 🧠 **이름부터 "FEA-AI 하이브리드"** 다 — 결정론적 유한요소해석(FEA)이 판정을 맡고 LLM은 탐색·설정을 맡는 분업. 위 takeaway ⑤(금융)·[[AI-주간-소식-2026-W31]](의료·건설)에 이어 **같은 처방의 4번째 도메인**이고, 이번엔 산업 뉴스가 아니라 **논문 제목에 구조가 박혀 있다**.
- **CyberNeuro: A Privacy-Preserving Agentic Workbench for Cohort-Scale Neuroimage and Clinical Data Analysis** 📄 [2607.28841](https://arxiv.org/abs/2607.28841) — 📄 방법론은 크게 성공했지만 **대규모·고차원 데이터셋을 AI/ML에 쓸 수 있게 만드는 일이 결정적 운영 병목**이다. 기존 워크플로는 **메타데이터 큐레이션 등에 광범위한 수작업**을 요구.
- **SeekBrain: An Autonomous Multi-Agent System for Accelerating Neuroscience Discovery** 📄 [2607.29347](https://arxiv.org/abs/2607.29347) — 📄 **고도로 이질적인 데이터와 파편화된 워크플로**가 발견을 갈수록 제약한다.
  - 🧠 CyberNeuro·SeekBrain 둘 다 **"모델이 부족한 게 아니라 데이터 준비·워크플로 파편화가 병목"** 이라고 말한다. [[AI-주간-소식-2026-W31]] LH 「AI가 읽는 건 도면이 아닌 데이터」와 같은 결론이고, [[CogInsight-Generator]]가 산출물을 구조화 JSON으로 잡은 선택의 또 하나의 외부 근거.
- **The AnyLog Edge Data Fabric** 📄 [2607.28836](https://arxiv.org/abs/2607.28836) — 📄 산업·자율 시스템이 **생성 시점의 운영 데이터**에 즉시 반응해야 하는데, 기존 아키텍처는 그 데이터를 **중앙 플랫폼을 거치게** 요구한다.

**E. 저관련(전수 기록용, 2편)** — **Mode 0: RCU 보조 V2X 안전 통신** 📄 [2605.25431](https://arxiv.org/abs/2605.25431) *(v4, 3GPP 자원 할당)* · **오피오이드 위기 대응 다층 개입의 국소 처치효과 추정** 📄 [2601.03105](https://arxiv.org/abs/2601.03105) *(v3, 공중보건 통계)*.

### ➕ 3차 보강(8/4 영문·arXiv)에서 나온 연결점

🚨 🧠 **⑤ "턴"이 프런티어에서 먼저 사라지고 있다 — 내 툴의 산출물 문법이 걸린 문제**: [[CogInsight-Generator]]가 만드는 시나리오는 **턴 교대**를 전제로 한 그래프다. 그런데 8/4 자료 두 건이 같은 방향을 가리킨다 — 오픈AI GPT-Live는 아키텍처 이름부터 **`turnless speech model`** 이고, arXiv **Transcript-Managed Transformers**는 대화를 턴이 아니라 **경계 블록 채널로 분할**한다. 여기에 W31의 「AI쇼핑 예측형 에이전트(봇 선제 발화)」를 더하면 **턴 모델과 충돌하는 사례가 3건**이다. 🧠 결론: 턴 그래프를 버릴 필요는 없지만, **"턴 경계를 누가 어떻게 정의하는가"를 시나리오 스키마의 명시적 필드로 빼두는 것**이 장기적으로 채널 확장(음성·선제 발화)의 유일한 탈출구다 — 지금은 암묵적 전제로만 존재한다.

🧠 **⑥ 하네스가 "자작 자산"에서 "남의 인프라"로 바뀌는 분기**: [[AI-주간-소식-2026-W31]]은 *"에이전트 하네스가 현대 LLM 에이전트의 운영 인프라가 됐다"*(CHILL-Harness)와 *"좋은 하네스에는 상당한 전문가 노동이 든다"*(DREvo)를 기록했다. 이번 주 **MS가 그 노동을 오픈소스로 흡수**하기 시작했다(Orchard = 프레임워크 / Echoverse = 환경 / EvoLib = 지식). 🧠 [[올림푸스-Olympus]]·[[CogInsight-Generator]]가 자작한 하네스의 가치는 **"직접 만들었다"가 아니라 "내 도메인에 맞다"** 쪽으로 이동한다 → [[프로젝트-포트폴리오]] 서술에서도 하네스 자작을 자랑점이 아니라 **도메인 적합성의 근거**로 써야 한다(2차 보강 연결점 ①과 같은 논리의 인프라 버전).

🧠 **⑦ "LLM에게 물어보지 말라"가 이제 6개 도메인 — 그리고 이유가 바뀌었다**: 의료(LLM 심사관 편향) → 건설(LH) → 금융(中 DGNN+LLM 90%) → **모터 설계(FEA-AI 하이브리드)** → **멀티에이전트 조율(MARGIN)** → **에이전트 검증 일반(Beyond Component Testing)**. 앞의 네 개는 *"LLM이 틀릴 수 있어서"* 였는데, MARGIN이 더 근본적인 이유를 준다 — 📄 **자기보고 신뢰도는 모델 간 비교가 불가능**하다. 🧠 즉 멀티 LLM 티어링을 쓰는 순간 "모델 A가 0.9, 모델 B가 0.8" 은 **비교할 수 없는 두 숫자**다. [[CogInsight-Generator]]가 단계별로 다른 모델을 쓰려는 계획과 정면으로 맞물리는 제약이고, 판정은 반드시 **모델 밖의 결정론적 기준**(스키마 검증·실행 결과)이어야 한다는 결론이 여기서 완성된다.

🧠 **⑧ 분산시스템 논문이 내 회사 조직도를 설명한다**: **Beyond Byzantine**은 📄 *"조직 구조에서 부서 에이전트는 정직-고장 / 악의 이분법에 좀처럼 들어맞지 않고, 제한된 합리성을 보인다"* 며 **정보 비대칭 하 자기이익 에이전트**를 위한 합의 알고리즘을 제안한다. 🧠 이건 [[mailer|CS SmartHub]]가 CS팀·개발팀·해외사업 사이에서 실제로 마주하는 조건 그대로다 — 아무도 악의는 없는데 각 부서가 자기 관점의 정보만 올린다. 지금까지 이 위키는 그걸 *업무 프로세스 문제*로만 다뤘는데, **모델링 가능한 구조**로 보는 관점은 새롭다. 🧠 실무 적용: 여러 부서에서 들어오는 요구사항을 합칠 때 "누가 어느 정보를 못 보고 있는가"를 명시 필드로 남기는 접근(→ [[올림푸스-기획요청서-작성요령]] 후보, 연결점 ③과 같은 자리).

### ➕ 4차 보강(8/4 한국어 naver)에서 나온 연결점

🧠 **⑨ "시나리오+LLM 결합"이 이미 은행권 공식 사업으로 진입했다**: 우리은행 하이브리드 AI 상담봇은 "명확한 업무는 시나리오, 복잡한 문의는 생성형 AI"라고 명시한다. 이건 [[CogInsight-Generator]]가 6단계 파이프라인에서 구현하는 바로 그 분리다. 🧠 차이는 **규모와 고객사** — 우리은행은 전국 고객 대상이고 CogInsight는 특정 사내 CS팀 요구로 설계됐다. KB·신한도 같은 방향이므로, 이 아키텍처는 이제 **경쟁 차별점이 아니라 기준선**이 됐다 — 차별점은 "어느 도메인의 시나리오를 얼마나 정교하게 구성하느냐"로 이동한다.

🧠 **⑩ 매니패스트 + Claude 연동 → "기획 데이터를 AI가 직접 읽는" 흐름**: 매니패스트는 Claude·Cursor가 기획 데이터를 직접 읽어 코딩에 반영하는 연동을 추가했다. 🧠 [[CogInsight-Generator]]의 미래 방향 중 하나가 "생성된 Dialog JSON을 AI 코딩 도구가 읽어 챗봇 코드 자동 생성"인데, 그 패턴이 이미 다른 도구에서 실현됐다 — 매니패스트가 어떻게 구현했는지 살펴볼 가치가 있다(🧠 참고 후보).

🧠 **⑪ 같은 주에 "CPU" 키워드가 에이전트 오케스트레이션·ETF·SKT 제품에 동시에 등장**: CPU를 노리는 ETF가 상장될 정도면 투자 자금이 그쪽으로 이동하는 중이고, 그 자금은 다시 CPU 기반 에이전트 오케스트레이션 인프라에 투자된다. 🧠 [[올림푸스-Olympus]] 같은 로컬 멀티에이전트 파이프라인이 CPU를 주로 쓴다는 걸 감안하면, "로컬 에이전트가 비용 효율적"이라는 이야기의 하드웨어 버전이기도 하다.
