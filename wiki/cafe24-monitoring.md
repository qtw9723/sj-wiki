> 🧠 **"운영 챗봇의 상점별 상태를 사람이 일일이 보던 일"을 백오피스 + 매일 11시 자동 점검 메일로 바꾼 프로젝트.** [[내-프로필]]의 "크론탭 + 메일 보고서" 자동화 경험([[mailer]], [[schedule-reporter-kakao]])이 외부 서비스 모니터링으로 확장된 사례다.
> 📄 기존 백오피스(React + Express 프록시) 스냅샷을 받아와 **해지 감지 프로브, 월간 사용량 조회, 읽기 전용 모드**를 직접 얹었다(2026-09-16~17, 16커밋).

## 문제 📄/🧠
- 📄 고객사 쇼핑몰 플랫폼의 챗봇 운영 현황(상점 관리·일일 점검·로그/오류 통계)을 백오피스(`cafe24_backoffice`)로 관리한다. 상점이 **해지**되면 API 인증이 막히는데, 이를 사람이 눈으로 알아채야 했다(프로브 도입 배경, `tools/cancel_probe/probe.py` 설명 근거).
- 🧠 해지 시점·월별 사용량을 한눈에 보는 수단이 없어 수작업 집계가 필요했을 것으로 보인다(추론; 저장소엔 배경 서술 없음).

## 내 역할
- 📄 저장소 첫 커밋이 `import ..._master snapshot (로컬 작업용)`이므로 **백오피스 본체는 받아온 코드**이고, 이후 15커밋(해지 감지·사용량·로컬 안전장치)이 내 작업이다.
- 📄 사용자 확정(2026-10-27): 전부 개인 프로젝트. 원 소유·팀 역할 분담은 저장소에 없음.

## 기능
**백오피스 본체(받아온 것) 📄** — `cafe24_backoffice/README.md`
- 상점 관리 / 일일 점검 / 챗봇 대화 로그 조회 / 로그·오류 통계 집계·대시보드 차트, 한/영 i18n.
- 백엔드는 **자체 DB 없이 외부 API의 인증 프록시**(키는 서버가 헤더로 주입 → 브라우저에 노출 안 됨). 프론트 빌드를 백엔드 `public/`에 복사해 프로세스 하나로 서빙.

**내가 추가한 것 📄 (git log 기준)**
- **해지 감지 프로브** `tools/cancel_probe` — 하루 1회 도메인마다 로그 count API를 호출해 응답을 분류, **연속 401 일수를 로컬 상태파일에 누적해 해지 감지일을 확정**. 외부 데이터에는 쓰지 않음. 변화가 있으면 **기존 데일리 메일에 합쳐 알림**.
- **상점 목록 해지일자 컬럼·정렬**, 해지 상점의 과거 사용량을 기록으로 보여주기, 백오피스 집계(log stats)로 보완.
- **월간 사용량 조회** `tools/usage_report` — 월 범위 계산·이름 정규화(보이지 않는 문자 제거)·해지요청 목록 붙여넣기(`--request-list`), CSV → 엑셀 변환, 백오피스 `/usage` 화면.
- **레이트리밋(429) 재시도**.
- **로컬 ESD 읽기 전용 모드**(`ESD_WRITE_ENABLED=false`) — 로컬에서 저장해도 운영 데이터가 바뀌지 않게 하는 안전장치.
- 해지 요청일 입력란 분리는 만들었다가 같은 날 **Revert**(2026-09-16).

**운영 자동화 📄(사용자 메모, 저장소 밖)** — 크론탭 매일 11:00 실행 스크립트(저장소 밖 별도 폴더), 알림은 Gmail SMTP로 발송. 08:00은 클램셸 절전으로 스킵되어 11:00로 이동. 같은 Gmail 계정 재사용 → [[mailer]]의 발송 구조와 연결.

## 기술
- 📄 프론트: React 19 · react-admin 5.7.4 · MUI 6 · Vite 6 · TypeScript 5.7 · Playwright 테스트. 백엔드: Node + Express 5(프록시 단일 `server.js`). 컨테이너/PM2 설정 파일 포함.
- 📄 도구: Python 표준 라이브러리 위주(urllib 등) + 단위 테스트(`tests/`). 의존성 버전 고정(2026-09-16 chore).
- 🧠 [[공통-기술스택]]의 React 계열과 겹치지만 react-admin은 이 프로젝트 고유.
