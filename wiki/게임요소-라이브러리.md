> 🧠 설계 핵심: **(1) 한 페이지 = 한 요소**, **(2) 정해진 값만 쓰는 frontmatter 속성(패싯)** 으로 분류, **(3) 사람은 Obsidian Bases 표로, Claude는 grep으로** 같은 속성을 검색. 폴더가 아니라 속성이 분류 체계다.
> 🧠 착수 전 구상·배경은 [[개발-위시리스트-게임요소-라이브러리]]. 이 페이지가 **규약의 정본**이다.

## 1. 기본 원칙
1. **한 페이지 = 한 요소(원자 단위)**. 한 페이지는 "이건 뭐고, 어떻게 쓰나" 한 가지 질문에 답한다. 독립적인 것이 둘 이상 섞이면 쪼갠다.
2. **분류는 폴더가 아니라 속성**. 위키 규칙(플랫)대로 `wiki/`에 두고, 파일명 접두사 + frontmatter 속성으로 구분한다.
3. **정해진 값만 쓴다(통제 어휘)**. 속성 값은 아래 §4 어휘표에 있는 것만. 새 값이 필요하면 **어휘표에 먼저 추가**하고 쓴다. (오타·동의어가 섞이면 검색이 무너진다.)
4. **중복 대신 링크**. 시스템 페이지는 하위 메커니즘을 복붙하지 않고 링크한다. 같은 요소가 여러 게임에 있으면 요소 페이지 하나 + 출처 게임 여러 개.
5. **출처·근거 표기**. vault 규칙대로 📄 자료 / 🧠 판단을 구분하고, 특히 **수치는 실측·공식·추정을 반드시 구분**.

## 2. 요소 유형 (`gl_type`) — 무엇이 담기나
| gl_type | 담는 것 | 예 |
|---|---|---|
| **기획** | 컨셉·코어 루프·내러티브 구조·BM·콘텐츠 구조 (왜·무엇) | 코어 루프 "탐험→수집→강화", 시즌제 BM |
| **시스템** | 여러 메커니즘이 엮인 하위 체계 | 성장 체계, 경제 체계, 전투 체계 |
| **메커니즘** | 단일 규칙·동작 | 대시 캔슬, 콤보 게이지, 도감 완성 보상 |
| **수치** | 밸런스 공식·성장 곡선·확률표·드롭 테이블 | 경험치 곡선, 데미지 공식, 가챠 확률 |
| **레벨** | 레벨 디자인·난이도 곡선·페이싱·맵 구조·튜토리얼 흐름 | 메트로배니아 잠금-열쇠 맵, 3막 페이싱 |
| **디자인** | UI/UX·게임필(피드백·연출)·아트 방향·사운드 연출 | 히트스톱, 데미지 숫자 팝업, 인벤토리 UI |
| **코드** | 구현 패턴·알고리즘·스니펫 | 상태 머신, 가중 랜덤, 오브젝트 풀 |
| **사례** | 게임 1개 단위 허브(출처 묶음) | 할로우 나이트, 뱀파이어 서바이버즈 |
| **조합** | 요소 조합 실험·새 게임 아이디어·회고 | "도감+로그라이크+방치" 실험 |

- 🧠 "레벨링"은 두 의미 모두 수용: **레벨 디자인 → `레벨`**, **캐릭터 성장(경험치·스탯) → `수치`(곡선) + `시스템`(성장 체계)**.

## 3. 파일명 규칙
- `게임요소-<유형>-<이름>.md` — 예: `게임요소-메커니즘-대시-캔슬.md`, `게임요소-수치-경험치-곡선.md`, `게임요소-사례-할로우-나이트.md`, `게임요소-조합-도감-로그라이크.md`
- 공백 대신 `-`. 이름은 **일반 명칭**(게임 고유 이름보다 장르에서 통하는 이름) 우선.
- `gl_status: 검증`이 된 페이지는 **이름 변경 금지**(링크·코드 참조 안정성).

## 4. 속성(frontmatter) 규약
### 4-1. 필수
```yaml
---
title: 게임요소 — <이름>
category: 게임 요소
gl_type: 메커니즘            # §2 중 하나
gl_domain: [전투, 이동]       # §4-3 도메인, 1~3개
gl_experience: [도전, 감각]   # §4-3 경험, 1~3개
gl_status: 정리              # 수집 | 정리 | 검증 | 폐기
tags: [게임요소]
source: <게임·공략·강연 URL / raw 파일>
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```
### 4-2. 선택 (해당될 때만)
| 속성 | 값 | 용도 |
|---|---|---|
| `gl_games` | `["[[게임요소-사례-…]]"]` | 이 요소를 쓴 게임들 |
| `gl_genre` | 장르 목록(§4-3) | 장르로 좁히기 |
| `gl_parent` | `"[[게임요소-시스템-…]]"` | 상위 시스템 |
| `gl_requires` | 링크 목록 | 이게 있어야 동작하는 요소 |
| `gl_synergy` | 링크 목록 | 잘 맞는 요소(조합 탐색용) |
| `gl_conflict` | 링크 목록 | 충돌하는 요소 |
| `gl_engine` | `msw` `unity` `godot` `web` `범용` | 코드·구현 대상 |
| `gl_lang` | `lua` `ts` `js` `csharp` `gdscript` `의사코드` | 코드 언어 |
| `gl_difficulty` | 1~5 | 구현 난이도 |
| `gl_evidence` | `실측` `공식` `추정` (목록 가능) | 수치의 근거 수준 |
| `gl_license` | `자체작성` `MIT` 등 | 코드 출처 라이선스 |
| `gl_repo` | 경로/URL | 큰 코드가 있는 별도 저장소 |

### 4-3. 통제 어휘 (값 추가는 여기 먼저)
- **gl_experience** (🧠 MDA 프레임워크의 8가지 재미 기반): `감각` `판타지` `서사` `도전` `교감` `발견` `표현` `소일`
  - 감각=보고 듣는 쾌감 · 판타지=역할 몰입 · 서사=이야기 · 도전=극복 · 교감=함께 · 발견=탐험·비밀 · 표현=꾸미기·빌드 · 소일=가볍게 시간 보내기(방치·반복)
- **gl_domain**: `전투` `이동` `성장` `경제` `수집` `탐험` `퍼즐` `생존` `건설` `소셜` `내러티브` `리텐션` `수익화` `온보딩`
- **gl_genre**: `액션` `RPG` `로그라이크` `메트로배니아` `퍼즐` `시뮬레이션` `전략` `방치` `플랫포머` `슈팅` `리듬` `카드` `샌드박스`

## 5. 본문 템플릿 (유형별 필수 섹션)
```markdown
> [!tip] 핵심 takeaway
> 한 줄 정의 + 내 게임에 쓸 때 포인트

## 핵심 규칙        — 정의와 동작 방식
## 왜 재밌나        — 플레이어 경험(gl_experience 근거)
## 출처 게임별 변형  — 게임마다 어떻게 다르게 썼나
## 조합 궁합        — 잘 맞는/충돌하는 요소와 이유
## 구현 메모        — 난이도, 주의점, MSW 등 엔진별 포인트
## 관련 문서
```
| gl_type | 추가 필수 섹션 |
|---|---|
| 수치 | `## 공식·표` (각 수치에 📄실측/📄공식/🧠추정 표기) · `## 조정 손잡이`(무엇을 바꾸면 어떻게 변하나) |
| 레벨 | `## 구조도`(ASCII·mermaid·이미지) · `## 난이도·페이싱 흐름` |
| 디자인 | `## 레퍼런스 화면`(직접 찍은 스크린샷만, `raw/assets/`) · `## 피드백 타이밍` |
| 코드 | `## 인터페이스`(입력·출력·상태) · `## 코드` · `## 테스트 방법` |
| 기획 | `## 코어 루프` · `## 목표 플레이어` |
| 사례 | `## 이 게임에서 뽑은 요소`(요소 페이지 링크 목록) · `## 한 줄 평` |
| 조합 | `## 재료 요소` · `## 가설(왜 재밌을까)` · `## 실험 결과·회고` · `## 토큰 실측` |

## 6. 코드 규칙
- 페이지엔 **핵심 스니펫(약 80줄 이하) + 의사코드**만. 실행 가능한 큰 코드는 **별도 git 저장소**에 두고 `gl_repo`로 링크(🧠 위키는 노트, 코드는 저장소).
- 코드 블록엔 언어 태그 필수, 첫 줄 주석에 `엔진/버전 · 테스트 여부`.
- **상용 게임 코드 복제 금지**: 역공학([[REA-Reverse-Engineer-Anything|REA]] 등) 결과는 **동작·수식만 글로 기록하고 코드는 직접 재작성**. 오픈소스 코드는 라이선스 확인 후 `gl_license` 표기.
- 에셋(그래픽·사운드)은 저장하지 않는다. 레퍼런스 화면은 직접 찍은 스크린샷만.

## 7. 상태 흐름 (`gl_status`)
`수집`(메모·링크 수준) → `정리`(§5 템플릿 채움) → `검증`(직접 구현·프로토타입으로 확인) → (`폐기`: 틀렸거나 쓸모없음, 삭제 대신 사유 남김)
- 🧠 검색할 때 `검증`이 가장 믿을 만하다. 조합 실험에서 실제로 써본 요소는 `검증`으로 올린다.

## 8. 검색 시스템
### 8-1. 사람 — Obsidian
- **Bases 표**(§0, `게임요소-라이브러리.base`): 뷰 전환 + 열 머리 클릭 정렬 + 필터 추가.
- **Obsidian 검색창 속성 검색**: `[gl_type:코드] [gl_engine:msw]`, `[gl_experience:수집]`, `[gl_status:검증] 대시`
- **그래프 뷰**: `gl_synergy`·`gl_requires` 링크로 요소 간 관계 확인. 필터에 `file:게임요소-` 입력.
- **백링크**: 사례(게임) 페이지를 열면 그 게임에서 뽑은 요소들이 백링크로 모임.

### 8-2. 기획할 때 찾는 순서 (권장 흐름)
1. **경험** — 플레이어가 뭘 느끼게 할까? (`경험으로 찾기` 뷰)
2. **도메인** — 그걸 어느 영역에서? (`도메인별` 뷰)
3. **기획·시스템·메커니즘** — 구체 규칙 고르기
4. **수치·레벨·디자인** — 조정 손잡이·흐름·연출
5. **코드** — 엔진에 맞는 구현 (`코드` 뷰, `gl_engine` 필터)
6. **조합** — `gl_synergy`/`gl_conflict` 확인 후 `게임요소-조합-…` 페이지에 기록

### 8-3. Claude — 검색 규칙
- 라이브러리 질문을 받으면 **이 허브 → frontmatter grep → 관계 링크 추적** 순서로 찾는다. 예:
  ```bash
  grep -l '^gl_type: 코드' wiki/게임요소-*.md | xargs grep -l 'gl_engine:.*msw'
  grep -l '^gl_experience:.*수집' wiki/게임요소-*.md
  grep -l '^gl_status: 검증' wiki/게임요소-*.md
  ```
- 결과는 페이지 목록 + 각 페이지 takeaway만 먼저 보여주고, 필요한 것만 본문을 읽는다(토큰 절약).
- 새 페이지를 쓸 때 **§4 어휘 밖의 값은 쓰지 않는다**. 필요하면 어휘표 추가를 먼저 제안.

### 8-4. 규모가 커지면 (🧠 나중)
- 수백 개를 넘어 Bases가 느리거나 복합 질의가 필요해지면 frontmatter를 그대로 SQLite/검색 앱으로 옮긴다. **속성 = 열**로 설계해 두었기 때문에 변환은 스크립트 하나로 가능.

## 9. 위키 운영 규칙과의 관계
- `index.md`에는 **이 허브 1줄만** 등록하고, 개별 요소 페이지는 Bases 표가 목차 역할을 한다(CLAUDE.md §4 예외로 명시).
- 건강검진(Lint) 때 추가로 점검: 필수 속성 누락 · 어휘 밖 값 · 끊긴 `gl_*` 링크 · 사례 없는 요소(`gl_games` 비어 있음, 경고만).
- 자동 위키화로 게임 자료가 들어오면 이 규약대로 요소 단위 페이지로 쪼갠다.
