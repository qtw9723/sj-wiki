> [!tip] 핵심 takeaway
> 🧠 **"청크 설정이 다른 저장소(store) 중 어디가 검색을 더 잘하나"를 감이 아니라 수치(정답 순위·MRR)로 비교하는 도구.** RAG 품질을 측정 가능한 문제로 바꾼 점이 포인트이고, [[CogInsight-Generator]] 계열 LLM·챗봇 작업의 검색 품질 판단에 쓸 수 있다.
> 📄 Python 표준 라이브러리만 쓰는 145줄 서버 + 단일 HTML. 설치 없이 `python3 server.py`로 실행.

## 문제 📄
- 같은 질의를 청크 설정이 다른 여러 docstore 저장소에 보내고, 결과를 한 화면에서 비교·분석해야 한다(README).

## 내 역할
- 📄 저장소에 명시 없음. 🧠 사용자 확정(개인 프로젝트)으로 기획·구현 전체로 본다. 첫 커밋이 `import from zip (2026-10-14)`라 이전 작업물을 가져와 git화한 것.

## 기능 📄
- **저장소별 성적**: 정답 포함 질의 수, 1위 정답 수, MRR, 평균 1위 점수, 정답 파일 아닌 결과 비율, 빈 셀 비율, Unnamed 열, 표 제목 정보 없음, PII 마스킹, 중복 청크, 응답 시간. 최고값은 초록 표시.
- **분석**: 수치를 바탕으로 저장소별 문제점과 최고 저장소를 문장으로 정리.
- **질의 x 저장소 표**: 칸에 정답 청크 순위, 클릭하면 청크 원문과 정답 문구 강조.
- **정답 판정**: 정답 문구를 줄마다 적고 모든 줄이 들어간 청크를 정답으로 봄. 표 기호·공백·`1000`/`1000.0` 차이 무시. 문구 여러 개면 "또는" 조건 판정(10-19). 한 문서 기준 검색 옵션.
- **저장/불러오기**: 결과 JSON 저장·재열기, CSV 내보내기, 테스트 세트 JSON 내려받기/올리기, 서버 없이 열리는 단일 HTML 리포트.
- 서버 API: `/api/config`, `/api/testset`, `/api/query`(검색 API 프록시). API 키는 로컬 서버에만 있고 브라우저로 전달되지 않음.

## 기술 📄
