### 11-11 묶음의 의외의 연결점 🧠
11-09 묶음처럼 제품이 아니라 **유형**으로 읽으면 내 프로젝트에 바로 대볼 거리가 3개 나온다.
- **IP 주소에 의존하는 인증(CVE-2026-107154) ↔ SmartHub 로그인 시도 제한**: 📄 [[delivery-smarthub]]의 시도 제한은 *"클라이언트별"* 이고, 검증 중 *"내 IP로 관리자 화면을 15분 잠근"* 기록으로 보아 IP 기준이다. 🧠 IP 기준 잠금은 두 가지를 확인해야 한다 — ① IP를 `X-Forwarded-For` 같은 헤더에서 읽는다면 공격자가 헤더를 바꿔 카운터를 피할 수 있는지(Ingress가 헤더를 덮어쓰는지) ② 여러 사용자가 같은 출구 IP(사내 NAT)를 쓰면 한 사람의 실패가 모두를 잠그는지. 이 공지는 "IP만으로 사람을 식별하는 것"이 약점이라는 같은 유형이다.
- **위험한 유형의 파일 업로드(CVE-2026-114432 Contact Form 7, CVE-2026-17399 API Connect) ↔ 업로드가 있는 내 프로젝트**: 📄 [[악보-아카이브-데이터-모델]]은 *"업로드 시점에 PDF로 정규화"*(D6)하고, [[notepad]]는 이미지 업로드(Supabase Storage), [[delivery-smarthub]] mailer는 서명 업로드가 있다. 🧠 확장자만 보지 말고 실제 내용(매직 바이트)으로 유형을 확인하고, 저장 버킷에서 실행·HTML 렌더링이 안 되게(Content-Type 고정·다운로드 처리) 하는 것이 이 유형의 기본 대책이다. 악보 아카이브의 PDF 정규화는 이 검사를 넣기 좋은 지점이다.
- **ModSecurity 해석 불일치(CVE-2026-104269) ↔ 공용 구성요소 보안 업데이트 건**: 📄 [[delivery-smarthub]] 보안 검토에서 공용 구성요소 중 보안 업데이트가 필요한 부분을 찾아 인프라 담당에 넘겼다. 🧠 웹 앞단 구성요소 이미지에 ModSecurity(libmodsecurity 3.x)가 들어 있는 경우가 있으니, 그 건을 확인할 때 내장 ModSecurity 버전(3.0.17 이상인지)도 같이 본다. ### 11-24의 의외의 연결점 🧠
- **"문서를 받아서 처리하는 서버" 유형 → [[delivery-smarthub]] doc-to-api**: 🧠 ONLYOFFICE Docs는 사용자가 올린 문서를 서버에서 열고 변환하는 제품이다. doc-to-api도 같은 일을 한다(OpenAPI·PDF·엑셀·워드를 받아 파싱). 그래서 이번 6건 가운데 둘을 내 쪽 점검 항목으로 옮길 수 있다.

  - **파일명·경로 외부 제어(110385·97727)**: 업로드된 파일 이름이 임시 파일 경로나 저장 경로에 그대로 쓰이는지 본다. 워드는 `mammoth`로 메모리에서 읽으니 해당이 적어 보인다. 확인은 하지 않았다.

- **인가 우회 2건(113627·113631) — 이달 10번째 인증·인가 계열 공지**: 🧠 [[SmartHub-모듈-보안-레벨-설계]]의 마스터 키 체크리스트 "인가" 항목에 해당한다. rapid7 글 주소에 *"from view-only access to container root"* 라는 표현이 있다. 🧠 보기 권한만 가진 사용자가 서버 최고 권한까지 올라가는 연쇄로 읽힌다(글 본문은 raw에 없어 확인 못 함).
