> [!tip] 핵심 takeaway
> 🧠 이번 묶음(11/05~07)에서 **나한테 실제로 걸리는 건 APT 하나**다. Ubuntu/Debian 서버·k8s 노드·Docker 베이스 이미지가 전부 대상이라 범위가 가장 넓다. OpenSSH는 *Alpine 이미지에 sshd를 직접 띄운 경우*만, Juneau·ELO는 *의존성에 있을 때만* 해당 → `pom.xml`/`package.json` 검색 한 번으로 끝난다.
> 🧠 교훈: 같은 CVE라도 **KISA 공지와 해외 집계 사이트의 범위·점수가 다르다**(아래 ⚠). 판단은 KISA·벤더 원문 기준으로 하고, 집계 사이트는 배경 설명용으로만 쓴다.
> 🧠 앞으로 이 페이지를 **KISA 보안공지 누적 허브**로 쓴다(매일 수집 자동화 검토 중 → [[#자동 수집 계획]]).

## 1. 2026-11 1주차 (11/05~07 공지)

### 1-1. OpenSSH (Alpine Linux) — CVE-2026-123158 "*sshole"
📄 KISA nttId 72288 (2026-11-07)
- **유형**: 비밀번호 처리 오류로 인한 **인증 우회**.
- **조건**: musl 기반이면서 PAM을 쓰지 않는 리눅스(Alpine 기본 설정 등)에서 비밀번호 인증이 켜져 있을 때. **glibc 배포판(RHEL·Ubuntu·Debian)과 `UsePAM yes` 환경은 영향 없음.**
- **해결 버전**: OpenSSH 10.6p2. Alpine 패키지는 edge `10.6_p2-r0`, 3.24 `10.3_p1-r2`, 3.23 `10.2_p1-r1`, 3.22 `10.0_p1-r11`, 3.21 `9.9_p2-r1`, 3.20 `9.7_p1-r6` … 3.16 `9.0_p1-r6`. **3.15 이하는 패치가 없으므로 상위 버전으로 이전.**
- **업데이트 후 sshd 재시작 필수.**
- 📄 (해외 보도) 원인: 256바이트를 넘는 비밀번호를 넣으면 musl `crypt()`가 오류값 `*`를 돌려주는데, 이 값이 "비밀번호 없음" 계정의 `*`와 같아서 로그인이 통과된다. 공식 클라우드 이미지의 `alpine` 계정은 비밀번호 없이 doas를 쓸 수 있어 root 권한까지 갈 수 있다. 임시 완화책은 `PasswordAuthentication no` 또는 `UsePAM yes`. 침해 흔적은 `/var/log/messages`에서 비밀번호 없는 계정의 `Accepted password`로 확인.
- 🧠 컨테이너는 호스트만 업데이트하면 고쳐지지 않는다. **이미지를 다시 빌드해야 한다.**

### 1-2. APT (Debian·Ubuntu 패키지 매니저) — CVE-2026-109518
📄 KISA nttId 72283 (2026-11-05)
- **유형**: KISA 표기는 "UNIX Hard Link 취약점". 📄 (해외 보도) 공격자가 중간자(MITM) 위치에서 HTTP 다운로드를 조작하면, 서명 검증을 통과한 뒤 패키지를 바꿔치기할 수 있다. 바뀐 패키지의 maintainer 스크립트는 root로 실행된다. Ubuntu는 CVSS 4.0 7.7(High)로 평가했다. 공격이 성립하려면 재시도(retry) 설정이 켜져 있어야 한다. 발견자는 Max Justicz.
- **해결 버전(주요)**:

| 배포판 | 해결 버전 |
|---|---|
| Ubuntu 22.04 | `2.4.15ubuntu0.1` |
| Ubuntu 24.04 | `2.8.4ubuntu0.1` |
| Ubuntu 26.04 | `3.2.1ubuntu0.1` |
| Ubuntu 3.3.x | `3.3.3ubuntu0.1` |
| Debian 12 / 13 | `2.6.2` / `3.0.4` |
| Debian 11 | `2.2.5` |
| Debian 1.8.3~1.8.5 | ⚠ **패치 미발표** → 지원 버전으로 전환 검토 |

- 권고문: USN-8996-1, DSA(debian-security-announce msg00526), DLA(lts-announce 11/msg00004).
- 📄 (Canonical) 업데이트 전 임시 완화책: 재시도 끄기 `Acquire::Retries "0";`
- 확인 방법: `apt changelog apt | grep CVE-2026-109518`
- 🧠 내부 미러·프록시 구간, CI 러너, 베이스 이미지도 점검 대상이다(MITM이 공격 조건이므로).

### 1-3. Apache Juneau — CVE-2026-96677 · CVE-2026-73100
📄 KISA nttId 72286 (2026-11-06)
- Juneau는 Java 객체를 JSON·XML 등으로 변환하는 라이브러리다(사용자 메모).
- **CVE-2026-96677**: XSS. 📄 (집계) 페이지 템플릿 변수가 HTML 인코딩되지 않는다.
- **CVE-2026-73100**: 민감정보가 로그에 남음. 📄 (집계) 기본 call logger가 서버 오류 요청의 헤더를 마스킹 없이 기록한다.
- **해결**: 9.2.1 이상.
- ⚠ KISA는 위 **2건만** 공지했다. 해외 집계 사이트에는 같은 시기 Juneau CVE가 5건 더 올라와 있다: 73098(Reflection Injection), 73117(HTTP 응답 분할), 73116(리다이렉트 시 인증 헤더 유지), 73101(예외 정보 노출), 121489(경로 탐색). 모두 9.2.1에서 수정됐다고 한다. 하지만 CVSS가 4.3~10으로 제각각이고 일부는 AI가 생성한 분석이다. 🧠 업그레이드 대상은 어차피 같으므로 9.2.1 이상만 지키면 된다.

### 1-4. enspirit ELO (`@enspirit/elo`) — CVE-2026-44267
📄 KISA nttId 72287 (2026-11-06)
- ELO는 노코드 플랫폼에서 사용자가 쓴 수식·조건식을 안전하게 실행하려고 만든 경량 표현식 언어이자 컴파일러다(사용자 메모).
- **유형**: XSS 및 코드 인젝션(GHSA-33r5-xmm8-v6x5). 📄 (집계) `.constructor.constructor`로 JS `Function` 생성자에 닿아 샌드박스를 탈출한다. Node.js에서는 임의 코드 실행, 브라우저에서는 XSS가 된다. 인증 없이 수식 문자열만 넣으면 되고 공개 PoC가 있다.
- **해결**: 1.0.1 이상.
- ⚠ 해외 집계에는 **CVE-2026-44266**(Ruby 컴파일 백엔드의 `#{...}` 보간 인젝션)도 있다. KISA 공지에는 빠져 있지만 역시 1.0.1에서 수정됐다.
- 🧠 "사용자 입력 수식을 안전하게 실행한다"는 것이 제품의 존재 이유인데 그 샌드박스가 뚫렸다. 내 프로젝트에서 사용자 조건식을 평가하는 기능(예: [[CogInsight-Generator]] 류의 조건 술어)을 만들 때도 **JS `eval`/`Function` 기반 샌드박스는 믿지 말 것**이라는 사례로 기억해 둔다.

### 1-5. 같은 주 KISA 공지 중 이 페이지에 정리하지 않은 것
📄 RSS 목록 기준: SonicWall(11/09), 인피니트헬스케어(11/07), 엠투소프트·에스티이지(11/06), Zyxel(11/05), WordPress(11/04). 🧠 내 환경과 관련이 적어 제목만 남긴다. WordPress는 개인 사이트를 운영하게 되면 다시 볼 것.

## 2. 대응 체크리스트 🧠
- [ ] Ubuntu/Debian 서버·노드: `apt changelog apt | grep CVE-2026-109518` → 없으면 `apt update && apt install --only-upgrade apt`
- [ ] Docker 베이스 이미지(ubuntu/debian/alpine): 재빌드 후 다시 배포
- [ ] Alpine에서 sshd를 띄우는 곳이 있는지 확인 → 있으면 openssh 업데이트와 sshd 재시작
- [ ] `grep -r "juneau" --include=pom.xml`, `grep -r "@enspirit/elo" --include=package.json` (로컬 저장소 전체)

**✅ 2026-11-09 가동 시작 (사용자 요구 확정)**: 평일 07:00 맥 launchd(아침 수집)가 먼저 수집한다(주말 공지는 월요일에 함께). 새 공지를 내 자산(저장소 의존성·서버 목록)과 대조해 등급을 나눈다.
- 📄 **긴급**: 내 프로젝트나 회사 프로젝트에 영향이 있는 공지. 데일리 브리핑 맨 위에 🚨 카드로 알린다.
- 📄 **경고**: 많이 쓰이는 제품이라 점검해 두면 좋은 공지. 브리핑에 경고로 알린다.
- 📄 **참고**: 나머지. 브리핑에는 제목만 싣는다.
- 🧠 이 공개 위키에는 공지 요약과 "점검 권장" 표시만 월별 페이지(`보안공지-YYYY-MM`)에 쌓는다. **자산·영향 정보는 공개하지 않는다.** 영향 분석은 비공개 vault에만 둔다.
- 📄 **수집 방식 보강(2026-11-09, 사용자 지적 "10건만 보이는 건 크리티컬한 한계")**: RSS는 최근 10건만 준다. 그래서 맥이 며칠 꺼져 있으면 공지를 놓친다. 이제 게시판 목록 페이지를 1쪽부터 넘기며, 이미 처리한 공지를 만날 때까지(최대 15쪽, 약 150건) 거슬러 올라간다. 상단 고정 공지는 건너뛴다. RSS는 목록을 읽지 못할 때만 쓴다.
