> [!tip] 핵심 takeaway
> 🧠 **지금 올림푸스는 "`bash run.sh` 단발"이 아니라 "큐 + 웹 UI + 원클릭" 중심으로 돌린다.** 평소 루틴 = ① `spec/<프로젝트>/`에 기획서 + **`run.env`**(대상 repo·게이트·권한·원격을 못박는 파일) → ② `Olympus.app` 더블클릭(또는 `olympus` alias) → ③ 웹 UI에서 등록 → ④ 폰(메일 `y` / GitHub·UI 답변)으로 개입만 처리.
> 🧠 놓치기 쉬운 3가지: **`run.env` 없이 버전 폴더 spec을 돌리면 엉뚱한 빈 폴더가 대상이 됨**, **UI/큐 무인 실행은 `PERMISSION_FLAG=--dangerously-skip-permissions`가 없으면 verify의 npm/deno가 막힘**, **`reset.sh`는 이제 `<프로젝트>` 인자 필수**.
> 📄 도구 개념·역할은 [[올림푸스-Olympus]], 기획서 쓰는 법은 [[올림푸스-기획요청서-작성요령]].

## A. 설치 / 부트스트랩 (기기당 1회)
> 🧠 **이 맥(주 기기)은 이미 완료.** 새 PC/노트북에서만 따른다.
> 📄 의존성 최소: **bash · git · python3(표준 라이브러리만) · Claude Code CLI · gh(선택)**. macOS/Linux/Windows(Git Bash·WSL).

### A-0. 사전 요구 확인
```bash
git --version ; python3 --version ; claude --version ; gh --version
```

### A-1. 클론
```bash
mkdir -p ~/IdeaProjects && cd ~/IdeaProjects
git clone https://github.com/qtw9723/olympus.git      # private (qtw9723)
```
- 📄 `PROJECTS_DIR` 기본 `~/IdeaProjects` — 대상 프로젝트들도 이 아래(`spec/<이름>/` → `~/IdeaProjects/<이름>`). 단 **기존 repo/버전 폴더는 `run.env`로 명시**(§B-1).

### A-2. Claude Code CLI 설치·인증
- 📄 run.sh가 `claude -p`(헤드리스)로 4역할 세션을 돌림. GUI 로그인 세션이면 `claude` 한 번 로그인, 헤드리스/서버면 `claude setup-token`.
- ⚠ 📄 `claude` 플래그(`--session-id`·`--resume`·`--add-dir`·`--model`·`--permission-mode`)는 CLI 버전마다 다를 수 있음 → 새 기기 첫 실행은 README **B(수동, 터미널 여러 개)**로 한 바퀴 검증 후 자동 권장.
- 🧠 macOS 기본 bash 3.2 대응 완료(별도 bash 업그레이드 불필요).

### A-3. 로컬 세팅 자동 적용 (`setup.sh`) 🆕
- 📄 `run.sh`/`queue.sh work` 시작 시 **자동 실행**: 저장소 `SETUP_VERSION`(현재 1) vs 기기 `state/setup.version`(git 미추적) 비교, 모자란 단계만 적용. v1 = **터미널 alias `olympus`**(zsh→`~/.zshrc`, 그 외→`~/.bashrc`)가 `start.command`를 가리키게 등록.
- 📄 수동: `bash setup.sh` · 끄기: `OLYMPUS_SETUP=0`. 새 기기는 풀 받고 한 번 실행하면 끝.

### A-4. `.env.local` — 알림 + 메일 승인 비밀 (`REMOTE=1` 쓸 때)
```bash
cd ~/IdeaProjects/olympus
cp .env.local.example .env.local
# .env.local 편집: SMTP_APP_PASSWORD 채우기 (값은 여기·위키에 적지 않음)
#   SMTP_SENDER=<발송 Gmail 계정>
#   SMTP_APP_PASSWORD=<Gmail 앱비번 16자, 공백 없이>
```
- 📄 값 하나가 **알림 발송(SMTP) + 최종 승인 답장 수신(IMAP)** 공용. `.env.local`은 gitignore. 비우면 알림/메일승인만 스킵되고 개발은 됨(최종 승인은 GitHub 경로 폴백).
- 🧠(메모리) 값 출처: [[mailer]]의 Supabase `sender_accounts`. 비밀은 **절대 위키/커밋에 기록 금지**.

### A-5. `olympus-inbox` repo 클론 (블로커·의도질문 GitHub 경로)
```bash
gh repo create qtw9723/olympus-inbox --private        # 이미 있으면 생략
cd ~/IdeaProjects && git clone https://github.com/qtw9723/olympus-inbox.git
```
- ⚠ 📄 run.sh가 **자동 클론하지 않음** — `INBOX_DIR`(기본 `~/IdeaProjects/olympus-inbox`)에 미리 있어야 `REMOTE=1`의 블로커/의도 경로가 동작. (최종 승인은 메일이라 inbox 불필요.)

### A-6. 스모크 검증
```bash
cd ~/IdeaProjects/olympus
bash test/run_tests.sh          # ALL TESTS PASSED (순수 bash·python, 네트워크 X)
set -a; . ./.env.local; set +a
echo test > /tmp/b && python3 notify.py --subject "smoke" --body-file /tmp/b --dry-run   # 발송 안 함
```
- 📄 `ALL TESTS PASSED`(큐·UI·원격·재개 테스트 포함) 나오면 부트스트랩 완료.
- 🧠 올림푸스는 sj-wiki launchd 자동 위키화와 무관한 별개 저장소. 기본은 **수동 실행**(원클릭 감시 모드 포함, cron 아님).

## B. 매 프로젝트 준비 (기획서 + run.env) ⭐

### B-1. `spec/<프로젝트>/` + `run.env`
- 📄 **한 프로젝트 = 하위 폴더 하나**(`spec/_README.md`). 작성 요령 → [[올림푸스-기획요청서-작성요령]]. spec/는 gitignore(가이드만 추적).
- ⚠ 📄 **greenfield가 아니면 `spec/<프로젝트>/run.env` 필수.** 폴더명=repo명으로 추측하는 기본값 때문에, 버전 폴더(`spec/<repo>-vX.Y.Z/`)를 그냥 돌리면 **엉뚱한 빈 폴더가 대상**이 됨(2026-07-09 실제 사고: 세션이 빈 폴더만 보고 개발 불가, 재기동만이 해법).
- 📄 `run.sh`가 `run.env`를 **자동 로드**(UI·큐 실행도 적용). 우선순위: **명시 env > run.env > config.sh 기본값**. 템플릿(값만 교체):
```bash
# spec/<프로젝트>/run.env
TARGET_REPO="$HOME/IdeaProjects/<실제-repo>"   # 반드시 존재하는 repo 절대경로
GIT_BRANCH="feat/vX.Y.Z-..."                   # 작업 브랜치(없으면 생성, 있으면 체크아웃)
AUTO_MERGE=0        # dev 개발: main 자동 머지 금지
DEPLOY_ON_DONE=0    # 자동 배포 없음
REMOTE=1            # 승인·질문을 폰/메일로
PERMISSION_FLAG="--dangerously-skip-permissions"   # UI/큐 무인 실행 필수 (§E)
VERIFY_CMD="<대상 repo의 build·test 명령>"
```

### B-2. 등록 전 프리플라이트 (📄 `spec/_README.md` 체크리스트 요약)
- [ ] `ls "$TARGET_REPO/.git"` — 대상 repo 실재
- [ ] `GIT_BRANCH`가 의도한 dev 브랜치
- [ ] **`VERIFY_CMD`를 repo에서 직접 돌려 green 확인** (못 통과하면 Builder↔Critic이 예산만 소진)
- [ ] `which deno node npm` — verify 전제도구 설치
- [ ] node 프로젝트는 `predev`/`prebuild`에서 설치 완주 확인(`node_modules/.package-lock.json` 없으면 `npm ci`) — 반쪽 설치로 `vite: command not found` 방지
- [ ] 새 기획이면 `bash reset.sh <프로젝트>`. **이전 요구사항 분석을 이어갈 거면 reset 금지**(분석 결과 삭제 → 전면 재분석)
- [ ] brownfield면 스펙에 "대상 repo `CLAUDE.md`/`AGENTS.md` 규약 준수" 한 줄 + 핵심 규약(dev/prod 환경, 마이그레이션, 하드코딩 금지 등) 재명시 — 규약 위반은 green이어도 Critic이 결함 처리

### B-3. state 초기화
- 📄 `bash reset.sh <프로젝트>` — **인자 필수**(2026-07-03 판의 무인자 `bash reset.sh`는 낡음). `state/<프로젝트>/`만 비우고 spec·config·runs 보존. 첫 실행은 자동 init이라 불필요.

## C. 단일 실행 (`bash run.sh`)
```bash
cd ~/IdeaProjects/olympus
bash run.sh                               # run.env가 있으면 그대로 적용
# 또는 env로 직접:
TARGET_REPO=~/IdeaProjects/<repo> VERIFY_CMD="<검증>" \
REMOTE=1 POLL_TIMEOUT_SEC=1800 PERMISSION_FLAG="--dangerously-skip-permissions" \
  bash run.sh
PROJECT=<이름> bash run.sh                # spec이 여럿일 때 프로젝트 지정(구 state 이행 재시작 시에도)
```
- 📄 **greenfield/brownfield 자동 판단**: `TARGET_REPO` 경로가 없으면 greenfield(`git init` + 범용 `templates/verify.sh`), 있으면 brownfield(작업 브랜치 `olympus/<프로젝트>-<타임스탬프>` 자동 생성, 동작 보존).
- 📄 `VERIFY_CMD` 기본 `bash verify.sh`. 기존 repo는 그 repo 명령(`npm run verify`·`pytest -q`·`deno test` 등).
- 📄 `run.sh`/`queue.sh work`를 돌리면 **웹 UI 서버가 백그라운드로 자동 기동**(끄기 `OLYMPUS_UI=0`).
- 📄 로그: `state/<프로젝트>/runs/run-*.log`.

### 노브 (필요할 때만) 📄 `config.sh`
| 변수 | 기본 | 용도 |
|---|---|---|
| `REMOTE` | 0 | 1=개입을 폰으로(블로커·의도=GitHub/UI, 최종승인=메일) |
| `POLL_TIMEOUT_SEC` | 21600(6h) | 원격 답 대기 상한. 초과 시 안전 폴백 |
| `PERMISSION_FLAG` | `--permission-mode acceptEdits` | 완전 무인은 `--dangerously-skip-permissions` (§E) |
| `AUTO_APPROVE` | 0 | 1=최종 승인도 생략 |
| `AUTO_MERGE` | 1 | 승인 시 기준 브랜치로 자동 머지(dev는 0 권장) |
| `DEPLOY_ON_DONE` / `DEPLOY_CMD` | 1 / 빈값 | 머지 후 배포. 규약 없으면 끝에 질문 |
| `ARCHIVE_ON_DONE` | 1 | 완료 후 기획서 `spec/_done/` + state 초기화 |
| `TOKEN_WAIT` | 1 | 사용량 한도 시 리셋까지 대기 후 자동 재개 (`TOKEN_RETRY_SEC` 1200 등) |
| `APPROVE_VIA_EMAIL` / `APPROVE_FROM` | 1 / `$SMTP_SENDER` | 승인 메일 답장 경로 / 허용 발신자 |
| `NOTIFY_MILESTONES` | 1 | 진행도 마일스톤 메일(§H) |
| `GIT_BRANCH` | auto | auto/none/이름 |
| `MAX_ROUNDS` | 6 | 작업당 Builder↔Critic 최대 라운드(라이트 모드는 3) |
| 모델 | 메티스 opus-4-8, **빌더·크리틱 sonnet-4-6** | ⚠ 2026-07-03 판의 "critic=opus"는 07-22 비용절감으로 낡음(생성자≠비평가 분리는 세션 분리로 유지) |

## D. 큐 + 웹 UI + 원클릭 🆕

### D-1. 큐 (`queue.sh`) — 여러 프로젝트 순차 소화
```bash
bash queue.sh add <프로젝트> [--mode lite]   # 등록(spec/<프로젝트>/ 필요, 기본 mode=auto)
bash queue.sh list                           # 큐 상태 표
bash queue.sh work                           # 1회 소진(큐 비면 종료, 종합 메일 1통)
bash queue.sh work --watch [초]              # 상시 감시: 비어도 대기, 등록되면 자동 실행
bash queue.sh migrate <프로젝트>              # (1회) 구 단일 state 이행
```
- 📄 상태는 `state/<프로젝트>/`로 완전 격리, 큐 단일 진실 = `state/queue.json`(UI도 이 파일로 대기열을 그림).
- 📄 모드: `auto`면 메티스가 분석 직후 규모 판정 → lite(작업 1~2개·라운드 상한 3, Critic·verify 게이트는 그대로) / full.
- 📄 **블로커여도 큐는 안 멈춤**: 그 항목만 `paused(blocker)`로 눕히고 알림 메일 → 다음 프로젝트 진행. 실패(`failed:verify`/`failed:crash`)도 항목만 기록하고 계속.
- 📄 **queue.json 소유권 계약**: 사람/UI = `queued/paused` 항목 추가·삭제·순서(배열 순서=우선순위)·mode·재개, `running` 항목엔 `request: pause|cancel`만. status/progress/result/paused_reason은 **워커 소유**.
- 📄 워커가 죽으면 다음 `work`가 스테일 running을 `paused(stale)`로 회수 후 계속.

### D-2. 웹 UI (`ui.sh`)
```bash
bash ui.sh            # 포그라운드 http://127.0.0.1:8765 (포트: bash ui.sh 9000 / OLYMPUS_UI_PORT)
bash ui.sh autostart  # 백그라운드 멱등 기동(run.sh/work가 자동 호출, 로그 state/ui.log)
bash ui.sh stop       # autostart로 띄운 서버 종료
```
- 📄 의존성 0(Python3 표준), **127.0.0.1 전용**. 모든 조작은 시맨틱 API(`/api/add·remove·reorder·mode·resume·request·answer`)를 거쳐 소유권 계약을 서버가 강제(락은 queue.sh와 같은 mkdir 락).
- 📄 **보기**: 대기열(상태 배지·진행바·result), 워커 상태, 항목 클릭→handoff.json+로그 tail, **실행 중 세션 패널**(역할·라운드·현재 작업·라이브 로그 2초 갱신), 헤더 **전 프로젝트 토큰 합계** + **`/usage` 사용량 대시보드**(프로젝트별·일자별·매트릭스).
- 📄 **조작**: 등록(spec/ 스캔 드롭다운)·삭제·↑↓·mode 변경(queued), 일시정지/취소 요청(running, 역할 턴 사이 반영), 재개(paused→queued), **결정 패널**(§G).
- ⚠ 📄 **워커 실행 자체는 터미널 소유**(`queue.sh work`). UI만 켜서는 등록해도 안 돌아감 → 원클릭(D-3)이 감시까지 같이 띄움. 최종 머지 승인 y/n은 UI 미지원(메일/터미널).

### D-3. 원클릭 시작 (2026-07-09) ⭐
- 📄 **`Olympus.app` 더블클릭** = 터미널 열어 `start.command` 실행 → ① UI 서버 기동 ② 브라우저 열기(`127.0.0.1:8765`) ③ **`queue.sh work --watch` 상시 감시**. 이후 UI에서 등록한 항목은 몇 초 안에 자동 실행. **중지 = 그 터미널 창에서 Ctrl+C.**
- 📄 Dock·/Applications에 복사 가능(저장소 밖이면 `~/IdeaProjects/olympus`를 찾음). `start.command` 직접 더블클릭도 동일. 터미널에선 `olympus` alias(§A-3).
- 🧠 평소 루틴: `olympus` → UI에서 등록 → 폰으로 개입 처리. 일회성 실행만 필요하면 `bash run.sh`.

## E. 무인 실행 권한 — `PERMISSION_FLAG` ⚠ 🆕
- 📄 기본값은 `--permission-mode acceptEdits`(파일 편집만 자동승인). `config.sh` 주석: 스캐폴딩 등 **명령 실행**이 많아 프롬프트로 멈출 수 있으니 완전 무인은 `--dangerously-skip-permissions`.
- 🧠(메모리, 실사고 기반) **UI/큐 무인 실행은 acceptEdits라 `npm`/`deno`(verify) 명령이 차단**되어 게이트가 못 돎 → **`run.env`에 `PERMISSION_FLAG="--dangerously-skip-permissions"` 필수.** 저장소의 실제 `run.env`(v0.5.1 spec)들도 이 줄을 포함(📄).
- 📄 UI/큐 실행은 세션 시작 시 작업 허용 디렉토리가 고정돼 **실행 중 권한 승인으로 못 고침 → 재기동뿐**이라, 등록 전에 `run.env`로 못박는 게 핵심.
- ⚠ 🧠 위험 플래그라 대상 repo가 dev 브랜치/격리된 곳일 때만. `AUTO_MERGE=0`·`DEPLOY_ON_DONE=0`을 함께 둬 프로덕션 반영은 사람 몫으로 유지.

## G. 장애 대응 / 재개 🆕

### G-1. 블로커로 paused → 답변 후 재개
- 📄 **웹 UI 결정 패널**: 멈춘 항목의 질문(`questions.md`)이 대기열 위에 뜸 → 답 입력 → **[답변하고 재개]** = `POST /api/answer` → `state/<프로젝트>/human-answers.md`에 기록 + 항목을 `queued`로 되돌림(자동 재개). 재개된 메티스가 답을 **최우선 반영**(같은 질문 반복 금지). `paused/blocker` 항목에만 가능, 빈 답 거부.
- 📄 가정으로 진행 중인 열린 질문(`open-questions.md`)은 참고용 표시(주석 플레이스홀더뿐이면 제외).
- 📄 대안: `REMOTE=1`이면 GitHub `## 답변`(run.sh가 `state/<프로젝트>/human-answers.md`에 반영). README는 "답변 후 항목 status를 `queued`로 되돌리면 재개(M0 재개 가드가 이어받음)"라고 안내.

### G-2. 안전 중지 (📄 README "안전 중지")
- 진행 상태는 전부 `state/` durable 파일 → **언제 중단해도 안전**, 재시작하면 M0 재개 가드+`progress.md`가 이어받음(최악: 중단 순간 돌던 역할 세션 하나 재작업).
- 터미널에서 돌면 **그 창에서 Ctrl-C**. 다른 세션이면:
```bash
pgrep -fl 'bash.*(queue|run)\.sh'     # 오케스트레이터 확인
kill <PID>                            # queue.sh work 먼저, 다음 run.sh (TERM이면 충분)
pgrep -lP <run.sh PID>                # 남은 자식(역할 세션·tee) 있으면 개별 kill
```
- ⚠ **`pkill -f claude` 금지** — 다른 Claude Code 세션까지 죽음. 자식 PID를 확인해 개별 정리. verify 중이었다면 대상 repo 잔여 프로세스(npm/pytest) 확인.
- 📄 진행 확인: `tail -30 state/*/runs/run-*.log`.

### G-3. 재시작·재개 일반
- 📄 **토큰 한도**: 감지→리셋까지 대기→자동 재개(`TOKEN_WAIT=1`). ⚠ 대기는 **실행 중 프로세스 안**에서만 — 터미널 닫기·로그아웃·재부팅·**클램셸 절전으로 프로세스 종료 시 유실** → 다시 `bash run.sh`(또는 `olympus`/`queue.sh work`)로 durable 상태에서 이어감. 자동 재실행 supervisor는 후속 과제.
- 📄 **워커 사망**: 다음 `work`가 `paused(stale)`로 회수 → UI에서 [재개].
- 📄 **구 레이아웃 state 재시작**: 루트 `state/`에 구버전 흔적이 있으면 `state/<프로젝트>/`로 자동 이행. spec이 여럿이라 추정 불가면 안전 중단 → `PROJECT=<이름> bash run.sh`.
- 📄 **재개 시 재기획 스킵 가드**(07-23): backlog에 `[done]/[doing]/[todo]` 마커 + task.md 존재 + status≠needs_clarification이면 재개로 보고 메티스 M0 재분석 생략(재기획 비용 $33~$88/회 절감). 새 기획인데 재시작으로 오판되면(구 버그: 플레이스홀더 오인, 07-23 수정) `reset.sh <프로젝트>`.
- 📄 **verify fork 폭탄**(07-15 수정): `run.sh`가 `TARGET_REPO`/`VERIFY_CMD`를 export + verify.sh 재귀 가드. 증상(`VERIFY_EXIT=128` 반복, `Resource temporarily unavailable`)이 보이면 구버전 → 풀 받기.
- 🧠 로컬 임시 감시 스크립트(`state/oly-budget-cap.sh`·`oly-token-monitor.sh`·`oly-resume-7pm.sh`)가 있음 — **git 미추적, 특정 큐 항목 id에 묶인 일회성 도구**(예산 초과 시 `request=pause` 걸기, 19:00 재개 예약). 재사용하려면 id·경로 수정 필요. 표준 기능 아님.
