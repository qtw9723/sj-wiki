# 악보 아카이브 프로젝트 기획 대화 원본 (2026-08-27, 사용자 구술)

출처: Claude 대화(코워크 세션). 사용자가 구술로 전달한 요구사항 원본.

## 1차 — 골자 9개 항목

찬양팀에서 사용할 것. 골자는

1. 악보들의 아카이브화
2. 매번 선곡되어 짜여지는 예배 곡목에 대한 기록 및 메모 기록
3. 선곡된 곡목의 빠른 배포
4. 핸드폰(패드) 어플화
5. 악보별 메모 기록
6. 악보 검색의 다양성
7. 악보 저장은 nas 혹은 클라우드에 해두고, 웹이나 앱에서 불러서 사용하는 방식
8. 실전에서 악보 뷰어로서의 기능
9. 로그인 및 회원관리 필요 / 부서별 관리

## 2차 — 원본 형식·곡모음·메모

- 악보 원본은 PDF, 이미지 파일 등 다양한 형태일 것
- 가능하다면 이미지 스캔을 통해서 메타데이터 생성하고 검색에 활용하면 좋겠는데 여의치 않으면 이건 패스
- 다양한 원본 형식의 악보들을 하나의 곡모음으로(예를 들어 이번 주일 찬양 곡목) 모아서 사용자들에게 제공할 것
- 이 경우 하나의 pdf 파일로 올라오면 제일 좋음
- 각 악보에 송폼도 같이 기재되면 더 좋음
- 사용자별로 펜슬이나 타이핑으로 메모한 게 저장되어 있으면 더 좋을 것 같음

## 3차 — 결정 사항 6개

1. 메모 레이어 분류하는 거 너무 좋고, 보여줄 때 필기가 따라올 수 있게 악보별로 좌표로 붙이는 거 너무 좋아, 꼭 하나의 PDF일 필요는 없지
2. 송폼은 그럼 자동추출 말고, 공용메모로 활용하면 될 것 같아
3. 스캔은 1단계와 가사 정도만 스캔해서 검색에 활용해도 문제 없어. 나머지 정보는 메모로 처리해도 될 것 같아
4. 원본 형식은 각자 다르게 하되, 다른 형식이면 pdf로 전환해서 저장하는 방식으로 하면 좋을 것 같긴 해
5. 뷰어 오프라인 캐싱은 있으면 좋겠지만, 메모를 사용할 거니까 고려해서 구성해야 할 것 같아. 캐싱해서 보여주되 중간에 인터넷 연결되면 새로고침 한다든지(그럼 그동안 작성한 메모도 없어지면 안 되겠지)
6. 배포는 우선은 링크로 만들고 웹 기반의 모바일 앱 배포로 할까 생각 중이야

## 4차 — 규모·현황·팀

- 찬양팀은 우선은 20명 내외인데, 나중에 비슷한 규모의 찬양팀이 여러 개 추가될 수 있을 것 같아. 이건 추후에 고려해도 될 것 같아
- 현재는 카톡으로 pdf를 공유하고 있어
- 개발은 우선 나랑 백은률이라고 한 명이 더 있어. 둘이 진행할 예정이야

## 5차 — 사용 흐름

- 팀장이 곡목을 구성해서 링크로 전달
- 사용자는 링크를 통해서 웹에 접근, 악보를 확인하고 메모할 수 있는 구조
- 로그인이 자동으로 되면 참 좋은 부분
- 그냥 웹페이지에서도 접근 가능하게 되고, 이걸 앱으로 옮기게 되면 앱에서 알아서 접근해서 보면 되는 것

## 6차 — 지시사항

- 로그인 부분 잘 정의해둘 것(나중에 개발할 때 빼먹지 않도록). 팀 아이디도 마찬가지
- 카톡 로그인이 잘 될지 걱정되는 부분이 있으니 문제될 부분 검토. 어려우면 자체 로그인 시스템을 만들어야 함

## 관련 배경 (이전 대화에서 확인된 항목)

- 이전에 악보 조옮김 웹앱을 검토한 적 있음 — 추천 스택: React + OpenSheetMusicDisplay(프론트), FastAPI + music21(백엔드), Claude API로 OMR. 비상업적 사용자 약 100명 대상.
