2. "좋긴한데 L1도 문제가 있어 고객의 정보가 민감 정도가 다른거같아 어때"

## 웹 검색 (Claude 수행) — 질의와 요지
- "Grafana plugin signature levels…" → 5등급(Grafana/Enterprise/Community/Commercial/Private), 미서명은 기본 로드 거부. https://grafana.com/docs/grafana/latest/administration/plugin-management/plugin-sign/
- "Home Assistant integration quality scale…" → 품질 등급(Bronze~Platinum), 보안 등급 아님(부적합).
- "GitHub repository visibility … Danger Zone" → 위험 설정을 빨간 구역에 모으고 이름 입력으로 확인. https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility
- "Kubernetes Pod Security Standards…" → privileged/baseline/restricted + enforce/audit/warn 모드, 네임스페이스 라벨, warn으로 먼저 보고 승격하는 도입 패턴, 시스템 네임스페이스 예외. https://www.kubernetes.io/docs/concepts/security/pod-security-standards · https://snyk.io/blog/understanding-kubernetes-pod-security-standards/
- "Android permission protectionLevel…" → normal(자동 허용)/dangerous(런타임 동의)/signature(같은 서명). https://developer.android.com/guide/topics/manifest/permission-element
- "data classification levels public internal confidential restricted…" → 4단계, 피해 기준 판정, 미분류=INTERNAL, 3~5단계 권장. Hack23 ISMS-PUBLIC CLASSIFICATION.md(ISO 27001 A.5.12). https://skills.cat/skills/hack23/cia/classification-policy · https://www.securityscientist.net/blog/data-classification-policy-template/ · https://learn.microsoft.com/en-us/training/modules/implement-data-classification-sensitive-information/2-explore-data-classification
